# SPEC-5.6 · 后端对照自测（真库语料，人手判定）

> 状态：实装（2026-11-17）
> 上游：SPEC-2.19（人工判定取样/计分）、SPEC-5.3（字面后端）、SPEC-5.5（语义后端接入）
> 定位：把 README「六·补」第 5 条落到工具上——**换后端前先用自己的问题判一轮**，不靠冻结集排名拍板。

---

## 一、为什么单列一件

冻结集证明的是「在 80 道题上谁强」；真库里 320 个实体、真实问法（含粤语口语）跟那 80 题不是一回事。SPEC-2.19 已经立了规矩：链接质量要人手判定，不自评。后端的取舍同理，只是判的不是边，是「这一问，哪边给出的前 3 张更像我要的」。

所以本件只做三样：**出并排对照单**、**只认人手判定**、**算胜率**。

## 二、语料与题源

- 库：**副本**（`--db` 必填，真库不动；切换后端会重建向量，只能在副本上做）。
- 题：`data/eval/backend-ab-queries.jsonl`，每行 `{ q, lang, kind }`；`lang` 取 zh / yue / en，`kind` 取 exact / paraphrase / 口语。首批 24 条按真库实体拟，owner 可增改。
- 口径：题面用「会真问出口的话」，不是关键词堆；粤语题用口语（嘅 / 咗 / 邊 / 搞掂）而不是书面转写。

## 三、取样与出单（`tools/backend-ab.js`）

1. 同一副本上先按**字面后端**（`hash-64w2`）`vectorStep` 全量重建，逐题取前 `k`（默认 3）；
2. 再按**语义后端**（`onnx-e5-small`）重建，逐题取前 `k`；
3. 出 md：每题一行，两列并排（各带可读标题），最后一列 `判定` 留 `?`。

- 两阶段必须**换后端重建**再取：同一副本向量表每实体一行，不重建就会拿旧后端的向量当新后端（SPEC-5.5 已立隔离规矩）。
- 出单是**只读 + 副本重建**：不动真库、不写任何生产状态。
- 确定性：同库同题同参数复跑，结果逐字一致（排序沿用 `vector.search` 的去重与同分规则）。

## 四、计分（`tools/judge-score.js` 扩展）

- 识别标题 `# 后端对照自测 · ab · N 条`，判值只收 `语义好` / `字面好` / `打平` / `都不好`。
- 指标：`语义胜率 = 语义好 / (语义好 + 字面好)`；`打平` 与 `都不好` 单列，不计分母；分母 0 输出「样本不足」。
- 仍未判（`?`）或格式错 → 拒收，点名行号，不出半个数。

## 五、验收（`test/test-5.6-backend-ab.js`）

| AC | 断言 |
|---|---|
| AC-1 | 对照表结构：表头含字面 / 语义 / 判定三列，行数 = 题数，判定列全为 `?` |
| AC-2 | 两列互不串源：字面列只来自字面后端、语义列只来自语义后端（假检索器记录调用） |
| AC-3 | 同题同参复跑，出单逐字一致 |
| AC-4 | 空题集 / 空库不抛，出表头与 0 行 |
| AC-5 | `judge-score` 能识别 ab 单：计数与 `语义胜率` 正确，分母 0 说「样本不足」 |
| AC-6 | ab 单留 `?` 或写错值 → 拒收并点名行号 |

## 六、Non-Goals

- 不自动判定（无模型、无启发式打分）。
- 不改发布默认、不改真库：切换与否仍由 owner 按这张单定。
- 不做统计推断（置信区间等）；样本就是样本，参照 SPEC-2.19。

## 七、已知边界

- 首批题由 agent 按真库实体拟，可能偏「文档标题口径」；owner 可增改后再跑，题源变化不算新版本（不进 FROZEN.json 的冻结约束）。
- 判的是「前 3 张卡里哪边更像要的」，不是绝对正确率；两边都不对就判 `都不好`，不进分母。
