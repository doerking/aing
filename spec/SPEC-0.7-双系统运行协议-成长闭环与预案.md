# SPEC-0.7 · 双系统运行协议（本能 × 意识 × 预判）

> **owner 缘起（2026-11-16）**：整个架构要让每一位 agent 把**无意识作为本能**、**意识作为决策与预判**。
> 实质：**agent 嘅一切回复、搜索展示、事由分析，才是 agent 成长嘅来源**（会话入库）。
> 所谓预判，系 **aing 从积蓄嘅知识发芽代谢**，配合用户嘅运行；**memo 备忘录把 agent 嘅注意力转到用户身边**，令用户嘅以往能第一时间被分析并给出**预案**。
> 角色：**主驾 agent（Hana）** 对用户；**aing 内成员**（自成长自优化）与主驾**隔着 memo**。

---

## 一、三个系统（一句话各自）

| 系统 | 一句话 | 谁执行 | 何时发生 |
|---|---|---|---|
| **本能** | 场域自动维护与提升，唔问人 | aing 内成员（场域）| 每轮代谢，永远跑 |
| **决策** | 主驾读 memo 证据卡，做继续/干预/退役 | 主驾 agent | 只在断点 |
| **预判** | 从积蓄知识发芽，生成用户预案 | 发芽代谢 + 预案器 | 主驾出场 / 用户新消息前 |

> 预判**唔系**独立嘅预言机，也**唔系**抽象分数；佢系「知识发芽 + 用户上下文」嘅合成产品，输出形态固定为**预案**。

---

## 二、成长闭环（唯一环）

```
用户 ──消息──▶ 主驾 agent（Hana）
                    │ 回复 / 搜索展示 / 事由分析
                    ▼
              会话入库（auto-ingest，服务端抽 tags，身份闸）
                    ▼
                 raw/  →  代谢（compile → … → 场域发芽）
                    ▼
              积蓄知识（entities / links / 场域证据）
                    ▼
              memo（注意力转向用户：以往 + 未闭环 + 预案）
                    ▼
              主驾出场先读 memo → 出预案 → 回复用户
                    └──────────── 回喂（命中/落空）────────┘
```

### 2.1 闭环不变量

| # | 不变量 | 检验 |
|---|---|---|
| G1 | **每次回复必入库**（回复 + 搜索展示 + 事由分析三源都入，唔只摘要）| 造一次会话 → 跑入库 → Conversation 实体出现且含三源字段 |
| G2 | 入库走身份/标签闸：客户端自报 tags 唔入 `tags` 列，只留「Agent 提议（未核验）」段 | C10i 回归 |
| G3 | 发芽必须有证据指针（原会话 id + 时间 + 原文行）| 任取一条发芽边，能追到会话原文 |
| G4 | memo 只带轻指针（标签 + 一行 + 证据 id），细节回库按标签取 | memo 体积上限 + 标签可取 |
| G5 | 预案命中/落空必须回喂事件（feedback），修正下次预判 | 造命中/落空各一次 → 场域证据数变化 |
| G6 | 冷启动诚实：无以往依据时，预案必须写「无以往依据」，唔准编 | 空库跑预案 → 输出 cold-start |

### 2.2 三源语义（为何三源都系成长）

| 源 | 增长什么 |
|---|---|
| **回复** | 判断方式、口径、表达偏好（用户点样接受/纠正）|
| **搜索展示** | 关注面（查了乜、对乜结果停留）|
| **事由分析** | 因果链路（点解做呢个判断），最高价值 |

> 只入最终回复 = 只存结论唔存推理；三源齐入，库先学到「点解」，而唔系「讲咗乜」。

## 三、预判 → 预案（核心交付形态）

### 3.1 定义
**预案** = 对「用户下一步会点、点解会噉」嘅有据推测 + 建议动作，一条一卡。

### 3.2 输入
- 当前用户消息（或出场信号）
- memo 用户面：以往主题、未闭环事项、偏好/雷区
- 库检索 top-N（按三轴 gate 过滤 + 场域带优先）
- 相似历史场景（同主题/同类型顺序出现 ≥2 次）

### 3.3 输出（每卡固定字段）
```js
{
  hypothesis: '用户接下来大概想……',   // 一句
  basis: [{ kind: 'conversation', id, at, quote }, ...],  // ≥1，可点回原文
  suggested: '建议动作（下一步做乜）',
  risk: '如果估错，代价係乜',
  confidenceBand: 'high' | 'mid' | 'low'  // 只准三档，唔畀假精确分数
}
```
- 一次最多 **3 卡**；无据则 1 卡 cold-start 说明。
- **禁止**：无 evidence 嘅断言、抽象浮点分、编造历史。

### 3.4 与场域的关系
- 预案嘅 `basis` 直接投喂场域提升证据（SPEC-0.6 I2：≥2 独立信号才可 promote）。
- 预案命中 → 回喂 `feedback` 事件 → 场域 `rebond`/`promote` 证据 +1。
- 预案落空 → 回喂 → 场域 `demote` 候选。
- 即：**预判同维护共用一套证据，唔另立账**。

## 四、memo 重构（注意力转向用户）

### 4.1 定位变更
旧 memo = 运维仪表台（健康/派单/链路面）。新 memo = **主驾睇用户嘅窗**：系统细节降为一行摘要。

### 4.2 新结构（用户面在前）
```js
memo.user = {
  recent: [{ sessionId, at, topic, outcome }],      // 最近 N 次（默认 5）
  openLoops: [{ id, text, since }],                 // 未闭环事项
  patterns: [{ pattern, evidenceIds, hits }],       // 以往模式（≥2 次才叫 pattern）
  plans: [{ hypothesis, basis, suggested, risk, confidenceBand }],  // 预案 ≤3
  coldStart: boolean
}
memo.systemLine = '健康 ok / 蒸馏债 0 / 场域上轮动作 2'   // 一行，仅摘要
memo.agentTodos = [...]                                   // 内成员自用，主驾默认唔睇
```

### 4.3 铁律
- **读端纯读**（C16 保持）：读 memo 唔投事件、唔写简报。
- memo 唔带全文、唔带附件清单；细节按标签回库取。
- 用户面空库时输出 `coldStart: true`，唔报错、唔编。
- memo 唔暴露内成员派单细节畀用户；主驾可按需展开。

## 五、角色边界（主驾 ⇄ memo ⇄ 内成员）

```
        用户
          │
     主驾 agent（Hana）            ← 唯一对外：决策、预判、应答
          │  读 memo（轻指针+预案）
          │  写 会话入库 / 事件（回喂）
     ─────┼─────  memo 是一道门，唔系总线
          │
   aing 内成员（内蜂群：自成长 / 自优化 / 场域维护）
```

| 边界 | 规则 |
|---|---|
| 主驾 → 内成员 | 只经 memo 读 + 事件写（取端常驻），唔直接调用 |
| 内成员 → 主驾 | 只经 memo 呈现（预案/证据卡），唔主动对话 |
| 内成员之间 | 场域内自洽，随包部署（SPEC-0.5）|
| 用户 | 只见主驾，唔感知内成员 |

## 六、对代谢线旧病的对应

| 旧病 | 本 spec 点治 |
|---|---|
| 守恒比 = 0（只剪不长）| 会话持续供料；G1 令发芽有原料，发芽产出入账 |
| 回炉单向泄漏 | G5 落空回喂 = 回炉触发器，唔再靠不触发的 recycle-seeds |
| 假成功（无产出报绿）| G3 证据指针：无证据嘅发芽/预案一律当无效 |
| 活性-连接脱节 | 三源入库带真实注意信号（搜索展示/事由分析）|
| hub 垄断 | 证据分散到会话来源，promote 需独立证据（0.6 I2）|
| 意识层只报现状 | memo 用户面 + 预案，从后验变前验 |

## 七、Acceptance Criteria

| # | 判据 | 检验 |
|---|---|---|
| AC-1 | 三源入库 | 造含回复/搜索展示/事由分析嘅会话 → 入库后实体可列三源字段 |
| AC-2 | 身份/标签闸 | 自报 tags 唔入 tags 列（C10i 回归）|
| AC-3 | 证据可追 | 任取预案/发芽，`basis` 能追到会话原文行 |
| AC-4 | 预案上限 | 输出 ≤3 卡，字段齐，`confidenceBand` ∈ {high,mid,low} |
| AC-5 | 无据不编 | 空库/无历史 → coldStart 卡，唔出现无 basis 断言 |
| AC-6 | 回喂闭环 | 命中/落空各一次 → 场域证据计数变化可查 |
| AC-7 | memo 纯读 | 连读两轮 state.json 字节一致（C16）|
| AC-8 | 用户面结构 | memo.user 五字段齐；systemLine 一行；无全文字段 |

## 九、Non-Goals

- 唔做通用预测模型、唔输出抽象概率分。
- 唔改入库存真源（仍系 `raw/` 与会话实体）。
- 唔令内成员直接同用户对话。
- 唔引入第三方编排/记忆平台。

## 十、一句话

**成长只认会话三源；预判只出有据预案；memo 一道门把主驾注意力转向用户；内成员喺门后自长自修；本能场域、意识决策、发芽预判共用一套证据账。**
