# SPEC-6.32 · 叙事工单口径对齐六段

> **一句话**：读数按六段算了，工单还在跟对方说「补到 400 字」——填几千字段外废话照样过验收。本轮把量长度和派单话术都对齐六段。

## 一、病证

| 叙事 | 段内字数 | 段外填充 | 修前 kq | 修后 kq |
|---|---|---|---|---|
| 六段各「无」 + 段外 4000 字 | ~6 | 4000 | **0.60**（过 0.50 验收） | 0.048 |

同时 `kq-low` 工单对叙事实体仍写「补正文到 400 字以上并有 ≥3 个标签」、slot 指 P2——接单方按话术交一篇长文，系统却按六段判，**需求与验收不同源**。

## 二、改法

**读数（kespi）**：叙事的正文长度只量六段正文（按标题切段后取六段名下的正文），不再量整篇 markdown。段外内容不进长度分。

**派单（self-optimize）**：`kq-low` 工单落库前看实体是不是叙事（`substr(content,1,120)` 命中 `capability-narrative-v1`）——是则换用 `kq-low-narrative` 需求：

```js
want: '把六段叙事写齐：场景/思维/手段/编排/产出/会话级校准，每段正文不少于 20 字，总正文 ≥ 400 字，并给 ≥3 个标签'
acceptance: [{ dim: 'kq', op: 'gte', value: 0.50 }]
mode: 'full', slot: 'P1', ttlRounds: 3
```

非叙事实体仍走原 `kq-low`（P2/semi）——分域不混。

## 三、Acceptance Criteria

| # | 判据 |
|---|---|
| AC-1 | 叙事 kq 只量六段正文：段外 4000 字填充不再抬分（< 0.3） |
| AC-2 | 六段齐全的叙事读数正常（≥ 0.6） |
| AC-3 | 低分叙事工单 demand 为 P1/full，want 提到六段 |
| AC-3b | 非叙事工单仍 P2/semi |
| AC-4 | 六段齐全的叙事不开 kq 工单 |
| AC-5 | `demandFor('kq-low-narrative')` 自校验通过 |
| AC-6 | 非叙事实体读数逐位不变（回归） |

## 四、边界

- 不改 `kq-low` 对非叙事的定义，不改验收算子（仍 `gte 0.50`）。
- 段外内容不是「丢掉」：它仍在库里、可被检索；只是不进 kq 长度分。
- 工单证据里的 `readings` 快照口径不变。

## 五、仍开着的

1. 六段齐全但内容跑题的叙事仍能过验收——语义层判官未接。
2. 真库 0 条六段叙事，本轮口径要等首批外部件进来才在真实工单上见效。
3. P1 仍由调用方注入，没有「注册—取单」自动化（与 6.28 同一条）。
