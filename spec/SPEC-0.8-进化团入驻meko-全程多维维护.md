# SPEC-0.8 · 进化团入驻 meko × 全程多维维护

> **owner 构想（2026-11-16）**：进化团旧院一直冇摆定位置（growth-loop / growth-director / guardrails / 三路 / 蜂巢全部旁挂 CLI）。今次加埋中间质 meko，**进化团入驻 meko**，**全程多维度进行维护**。
> 本 spec 是呢个摆位嘅唯一真源。与「四条独立 CLI 旁挂件」旧口径冲突处，以本 spec 为准。

---

## 一、裁定（一句）

**进化团唔再系外部旁挂嘅一组工具，而系 meko 中间质内部嘅常驻维护成员组（maintenance cohort）**：以 SPEC-1.15 组件契约注册进编排器，共享同一中间质（蜂巢形态），喺双铰链每一轮、每一段、每一个时点做维护判定，输出评分/提案/建议；实际写入只经编排器注入句柄同场域执行件（2.12/2.13）。

三条推论，即刻生效：

1. **唔设独立进程、唔设自己嘅调度器**。节律唯一来自 meko 编排器嘅 `runCycle`。
2. **唔设自己嘅库**。读写全部经注入句柄，与其它组件同一套 `entities / links / meko_cycles`。
3. **唔系主驾**。进化团改自己（成员基因、路由记忆、评估阈值候选）可自治；改架构/改主驾/改用户可见阈值，走 W2 审批 + memo 呈现。

## 四、全程多维度维护矩阵

「全程」= 四个时点；「多维」= 六个维护维度。每个格子必须落一件成员 + 一条可断言输出。

### 4.1 四时点（全程）

| 时点 | 位置 | 进化团做乜 | 输出 |
|---|---|---|---|
| **T0 轮前定焦** | `runCycle` 开始前 | 读上轮快照 + 健康灯 → 定本轮重点与预算分配 | 本轮 plan（`pilot`）|
| **T1 轮内复核** | 每轮 field 阶段（6/5/4）| 对场域动作候选做三路复核 + 三闸拦截 | 放行/拦截清单（`tri-cross` + `omni-gate`）|
| **T2 轮尾度量** | 每轮写 `meko_cycles` 后 | 守恒比、回炉闭环、hub 越线、KESPI 位移 → 评分与告警 | 本轮评分 + gene 候选（`gene-keeper`）|
| **T3 跨周期演化** | 每 N 轮 / 每夜 | gene 提升/衰减/归档、成员自评、阈值候选 | gene 落定 / 阈值候选（走 W2 若改可见阈值）|

### 4.2 六维（多维）

| 维 | 维护对象 | 断言（可测）| 主要成员 |
|---|---|---|---|
| D1 结构维 | 双链拓扑、边、度、断链 | 断链数唔升；hub 越线逐个有拆解记录 | `tri-cross` |
| D2 强度维 | 九段升降合规 | 任何跨带移动带证据；背景带唔准跳入口带 | `omni-gate` |
| D3 度量维 | KESPI 八维、守恒比、回炉闭环 | 每轮有快照；守恒比 ∈[0.8,1.5] 或出告警 | `gene-keeper` |
| D4 时序维 | 新鲜度、衰减、停滞 | 停滞 ≥3 轮触发 full_metabolism（沿用原院 9 动作语义）| `pilot` |
| D5 成员维 | 成员自身：基因、路由记忆、评估偏差 | 衰减到阈即归档；同一基因连续失败 3 次降级 | `gene-keeper` + `poll` |
| D6 用户维 | 用户侧供料 | 只出「提案/评分/建议」入 memo，**唔直接改用户面** | `pilot`（供料）→ 3.11/3.12 |

## 五、自治 / 审批边界

| 自治（成员自己拍）| 审批（W2 + memo）|
|---|---|
| 记录 episode/route/pattern | 改 KESPI 红黄阈 |
| 评估候选、出评分 | 改九段段位映射规则 |
| 出 plan、出提案、出告警 | 改 T_bound / 轮数 / 预算上限 |
| gene 内部衰减与归档 | 任何影响主驾行为或用户可见面嘅改动 |
| 建议回滚（执行仍由场域件）| 提升至入口带（7+）—— **双重锁**：场域证据 + 闸东放行 |

**原院教训**：guardrails 写咗但全仓无调用点（核读 §4.3）。本 spec 要求 `omni-gate` 必须被 `gene-keeper` 嘅 promote 路径**强制引用**，冇闸记录嘅 promote 一律拒绝。

## 十、修订 A · 外派蜂群三三制（嚼完抛）

> 资料依据：`aing/docs/Engineering/SWARM-33-DOCTRINE-2026-11-06.md`、`DISPATCH-TICKET-TEMPLATE-2026-11-06.md`、`SWARM-RESEARCH-2026-11-03.md §〇`、`dsh-aing-bridge/swarm33-*.js`（135 测）。
> 边界：守内（自维护）与对外（派工）**互不派单、不作桥接**（owner 2026-11-03 定）。两者只共同接住 meko：内为常驻成员，外为派出口与残渣吸收口。

### 10.1 常驻单位 3 员

- 基础单元恒为 **3 员**：主攻 / 助攻 / 掩护，正面不重叠、不留缝；单元长由主攻兼任
- 数量随业务增减，最低 1 单元，上限无；编制封顶 **营**（3–4 班 × 3 单元）
- 波次只管单内：1 前出 → 2 展开；禁三单元同刻起跑；**跨单永远并行**

### 10.2 派前基础范式先于任务链（顺序写死）

```
第一步 底版·人员设定：粤语思维×NLP（务实优先/阈值收线/留面/三分否定），输出普通话简体；
                      理解任务先于动手，开工先复述目标与验收口径
第二步 底版·标准工作流：理解 → 标签取料 → 消化 → 返回再解析（方案+口径先给人看）
                      → 执行（弹道落盘）→ 汇报（事实+真跑证据+可点 URL 证据指针）
第三步 工单头：单号 dispatch-<yyyymmddThhmm>-<slug> / handle swa-<单号段>-<位段>-<随机段> / gate
第四步 任务诉求：一句话目标 / 背景与禁碰区 / 验收补充 / 期限与规模
第五步 链路条款：①弹道落盘 ②心跳遗嘱 ③销毁前落盘 ④点间通道 ⑤收口挂主题标签
```

**缺底版拒派**——唔带条款唔派工（条令红线）。

### 10.3 使命不断推进（滚动派发）

- **单间不互斥**：旧单未收，新单照派；派新单唔打断原单
- 派发人靠链路面 last-feed + 心跳睇状态，**唔靠排队**；通道撞限只影响同刻起跑，唔构成排队理由
- 「收口」必须歼灭式：弹道齐套 + 标签挂齐 + gate 过，先算收干净；半收口 = 伤其十指

### 10.4 交接自然消逝

- 收工即散：承接者上下文销毁，**销毁前必须最后落盘一次**
- 只回残渣：结论 / 证据指针 / 失败原因；**唔回会话、唔留交接单、唔继承下一单**
- 料归料堆、人走人路：弹道按单号归账，唔按 handle 归人
- lost 不陪葬：弹道照吸收，单标 lost；返嚟但货唔合格先叫 failed

### 10.5 其余细设（承条令，唔重造）

四通道（基地来去 ×2 + 点间 ×2；跨点情报唔经派发人中转）／点间膜三档（全透/半透/不透，默认半透只过事实+指针）／伤亡续编（新随机段、同单失败≥2 改派单 agent 深工）／三问立项（对照组/阈值/检验时点缺一不立项）／基线对照（编队打唔过同预算单 agent 即砍编队）／可损耗（试错成本记零，弹道系唯一要保资产）。

### 10.6 与 meko 的接口（唔越边界）

| 口 | 内容 | 谁做 |
|---|---|---|
| 派出口 | meko 出派工包（底版+任务链），交宿主运行时 | `pilot` 出 plan，派发人执行 |
| 残渣吸入口 | 弹道回流走既有 ingest/代谢，**唔直写双链** | 摄取链（3.5），唔经进化团 |
| 监控 | 链路面/心跳异常入 D4 时序维 | `pilot` 狼位 |

**I7 外延**：外蜂群对双链零写权；残渣只经主线 ingest 入账。
