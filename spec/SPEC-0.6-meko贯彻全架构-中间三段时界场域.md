# SPEC-0.6 · meko 贯彻全架构 × 中间三段时界场域

> **owner 取态（2026-11-16）**：aing 全组件架构从头到尾转 DNA 范式；**meko 中间质同双铰链纠缠、贯彻全架构**；md 文档一律 Tolaria 格式 + 9 段设置；**meko 中间三段跑时界场域**，落实双铰链嘅维护同优化提升。
> 本 spec 是这份取态的**唯一实施真源**。与 0.2/0.3 冲突处，以本 spec 为准；0.2 接口签名、0.3 T_bound 算法保留。

---

## 一、目标（一句）

令 meko 唔再系旁挂嘅四件类，而系**所有组件都经佢编排**嘅中间质；9 段强度分成三带，中间带（6/5/4）系时界场域嘅唯一作业面，双铰链嘅维护同提升全部喺场域内发生。

---

## 二、三带架构（9 段 → 三带）

| 带 | 段位 | 名字 | 通信模式 | 谁作业 | 语义 |
|---|---|---|---|---|---|
| 左 | 9 / 8 / 7 | **入口带** | SLB 快车道 | 检索面（只读为主）| 已成立、可进检索入口；唔喺度做重活 |
| 中 | 6 / 5 / 4 | **场域带** | 时界场域（SLB/SLE 双模交替）| **meko 主场** | 全部维护与优化提升喺呢度发生 |
| 右 | 3 / 2 / 1 | **背景带** | SLE 慢车道 | 沉积/回收 | 只沉淀、只被消费，唔参与入口 |

**铁律一**：场域带之外的段位，meko 只做路由（升级/降级），唔做改造。
**铁律二**：背景带 ≤3 唔准直接跳入口带，必须经场域带连续晋升（1→3→5→7 每段要证据）。

## 三、meko 贯彻全架构（组件契约）

### 3.1 编排唯一入口
- 所有代谢组件**唔可以直接对 store 写**；只可以注册到 meko 编排器，由编排器注入句柄、给预算、按轮驱动。
- 旧院「组件各自读写 + 直线 11 步硬串」范式**作废**。

### 3.2 组件契约（每个组件必须声明）
```js
{
  id: 'compile',                  // 唯一名
  band: 'entry' | 'field' | 'background' | 'cross',  // 主要作业带
  reads: ['entities', 'links'],   // 读面（表级）
  writes: ['entities'],           // 写面（表级）
  budgetTick: 1,                  // 该组件的 base tick（喂 T_bound）
  reversible: false,              // 写动作是否可逆（不可逆动作须过冷备份门）
  onCycle: async (ctx) => ({...}) // 由编排器调用，ctx 含 store/db/band/evidence
}
```
- **不可逆动作**（物理删、覆盖写）一律禁止；确需执行的走显式迁移任务（M4）。
- 组件之间**唔直接调用**；只可通过编排器上下文交换数据（ctx.bus）。
- 契约实现落点：`src/meko-orchestrator.js` 暴露 `registerStep(contract)` / `runCycle(cycleType)`；静态检查 `tools/arch-lint.js` 扫 `src/*.js` 是否绕过编排直连 store（门禁 C5）。

### 3.3 meko 四顶在各带的角色

| 四顶 | 入口带 | 场域带（主场）| 背景带 |
|---|---|---|---|
| ① 氢键结合 | 读已结合的 raw⇄wiki 对 | **补键/断键（维护）** | 弱键待回收 |
| ② 组蛋白分层 | 门槛判定 7 起 | **分段路由 + 带内排队** | 沉底 |
| ③ 时界编排 | 只发快车道调度 | **场域作业本体** | 慢车道心跳 |
| ④ 双链互校 | 抽检 | **每轮互校 + 对返补齐** | 标记孤岛 |

## 四、时界场域（中间三段）

### 4.1 定义
一次场域 cycle = 对 `band ∈ {6,5,4}` 嘅实体/边执行三段式：

```
场域扫描（scan） → 场域动作（act） → 场域结算（settle）
```

- **扫描**：捞出中间带候选（按 kespi/活性/互校 gap 排序），入队。
- **动作**：只准 M 类（维护）同 U 类（提升）两种，见 4.2。
- **结算**：写 `meko_cycles`（含动作计数 + kespi_snapshot），超 T_bound 标 failed，唔无限等。

### 4.2 场域动作表

| 类 | 动作 | 作用 | 可逆 |
|---|---|---|---|
| M | `rebond` 补键 | raw⇄wiki 弱键缺失 → 补上 | ✅ |
| M | `unwind` 断噪 | 噪声弱键（互校矛盾/久未命中）→ 断开 | ✅ |
| M | `reconcile` 复校 | 双链 gap 对返，补漏需求 | ✅ |
| M | `demote` 降级 | 证据不足 → 7 降 6、6 降 4 | ✅（可再升） |
| U | `promote` 晋级 | 带证据（≥2 独立信号）→ 6 升 7、4 升 6 | ✅ |
| U | `sprout` 发芽 | 从场域带实体长出新候选（进 3–5 段）| ✅ |
| U | `pollinate` 授粉 | 跨链配对长出候选边（先进场域带，唔直入入口）| ✅ |

### 4.3 场域不变量（门禁断言）

| # | 不变量 | 检验 |
|---|---|---|
| I1 | 场域只处理 6/5/4；跨界必须显式 promote/demote | 造 7 段实体入场域 → 被拒并记账 |
| I2 | 提升必须带 ≥2 独立证据信号 | 无证据 promote → 拒绝并返回理由 |
| I3 | 所有场域动作可逆，误删=0 | 任取动作按逆操作还原，表内容逐字段一致 |
| I4 | 每轮结算必落 meko_cycles（动作计数 + kespi 非空）| 跑一轮查表 |
| I5 | 守恒闸：sprout 产出 / prune 数量 ∈ [0.8, 1.5] | 36 轮统计（挂任务 2.10）|
| I6 | 场域作业有界：单轮耗时 ≤ T_bound | 计时断言 |

## 六、文档 Tolaria 9 段（全仓可执行）

### 6.1 范围
`aing-v2/` 下全部 `.md`（除 `node_modules/`、`.temp/`）：`spec/`、`docs/`、根文档、`tools/` 说明。

### 6.2 格式（frontmatter 必含）
```yaml
---
tags: [域, 类目, 类目:N, ...]   # 至少 1 个 :7-:9 入口标签
description: 一句话
date: YYYY-MM-DD
---
```

### 6.3 强度语义（照 `raw/tag-taxonomy-rules.md`）
| N | 语义 |
|---|---|
| 9 | 身份（文档就系呢个主题）|
| 8 | 强关联（核心论据/直接组件）|
| 7 | 重要（深度涉及）|
| 5 | 默认（无 :N 落呢度）|
| ≤3 | 弱（仅背景；**唔准**挂加载入口类目）|

### 6.4 硬规矩
- 标签语法 `类目[:N]`，N ∈ 1–9；超出或 `:0` 即红。
- 单档 ≤20 个标签。
- 无 frontmatter / 无 description / 无 ≥7 入口标签 → 红。
- 执行：`node tools/doc-tags-lint.js`（门禁 C4）。

| # | 判据 | 检验 |

| AC-1 | 组件契约注册 | 假院注册 3 个步骤 → runCycle 按契约顺序驱动，组件唔直连 store |
