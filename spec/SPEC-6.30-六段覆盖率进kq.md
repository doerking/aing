# SPEC-6.30 · 六段覆盖率进 kq

> **一句话**：6.29 修好了「量哪段正文」，但没管「六段齐不齐」——只写一段的叙事只要字够多，分数与六段齐全的一样。覆盖率不进读数，外部件就没有动力写全。

## 一、病证

| 叙事 | 覆盖率 | 修前 kq | 修后 kq |
|---|---|---|---|
| 六段齐（4800 字） | 1.0 | 0.675 | 0.675 |
| 只有三段（2400 字） | 0.5 | 0.675 | 0.540 |
| 无标题正文（800 字） | 0 | 0.675 | 0.405 |

修前三者同分——「缺段」在读数层面不存在。

## 二、改法

```js
narrativeCoverage(markdown)   // 数六个固定小节标题命中数 / 6
narrativeFactor(content)      // 叙事：0.6 + 0.4 * coverage；非叙事：恒 1
kq = clamp01(原公式 × narrativeFactor(content))
```

- **覆盖率**只认标题行：`^#{1,4}\s*<段名>\s*$`（`m` 模式），段名按 `SECTIONS` 六键精确匹配。
- **惩罚下界 0.6**：不是「缺段直接归零」——正文本身仍有价值，只是拿不满；六段齐完全不打折。
- **只对六段叙事生效**：`narrativeBody(content) === content`（非叙事）时 factor 恒 1，三源实体读数逐位不变（AC-5 锁死）。
- 原 kq 公式的三段权重（长度 0.6 / 标签 0.25 / 置信度 0.15）不变，覆盖率是**乘子**不是第四项——避免重新分配权重引发全线漂移。

## 三、Acceptance Criteria

| # | 判据 |
|---|---|
| AC-1 | 覆盖率纯函数：六段=1、三段=0.5、无标题=0 |
| AC-2 | 六段齐不打折：读数与同长度纯文本差 ≤ 0.06 |
| AC-3 | 三段 ≈ 六段的 0.8（0.75~0.85） |
| AC-4 | 零段 ≈ 六段的 0.6（0.55~0.65） |
| AC-5 | 非叙事实体读数不受影响（同长度纯文本仍 0.675） |
| AC-6 | 覆盖率可重复计算，无状态 |

## 四、连带改动

- test-6.29 AC-2 的 fixture 从两段改为六段齐——它原本只验「正文长度别被 JSON 外壳污染」，两段的 fixture 在新规则下会被覆盖率合法扣分，会串味；改成六段齐才隔离得住。断言数不变（5）。
- `kespi.js` 导出增 `narrativeCoverage` / `narrativeFactor` / `NARRATIVE_SECTIONS` / `COVERAGE_FLOOR`。

## 五、边界

- 不验段内**内容质量**：只数段在不在，不判写得好不好。写「无」也算有段——这是形状层，不是语义层。
- 不回溯改写历史读数：`kespiStep` 下次跑到该实体会自然按新口径重算。
- `semi` 形态（系统自拼六段）覆盖率天然为 1（`buildCapabilityNarrative` 只给有内容的段渲染标题），不会被误伤。

## 六、仍开着的

1. 六段齐但有段是凑数的，读数仍满分——段**长度分布**（比如任一段 < 20 字算缺）是下一层可议的口径。
2. 真库仍是 0 条六段叙事，本轮的收益要等第一个外部件进来才能在实际读数上看到。
