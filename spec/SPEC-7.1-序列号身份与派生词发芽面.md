# SPEC-7.1 · 序列号身份 × 派生词发芽面

> 定调（2026-11-17）：知识进 aing 后 **表头只是序列号，aing 不处理它**；全部加工对象是正文。
> 新内容另有序列号（只追加，不改写）。关联由内容产生：**关键词能长出多少派生词、关联得越多，就是知识链**。
> 另两条硬要求：**粤语本身可以拆**（词素级）；**繁体是粤语最常用形、也是海外圈主用形**——生成器必须同时产繁体。

## 一、现状读数（2026-11-17 在实库副本上量）

| 项 | 值 |
|---|---|
| 实体 | 299 活跃 / 320 全库，id = 名字 slug（身份＝题头） |
| 关键词 | 92 个，无死端；但 72 个在强边下**一条外扩边都没有** |
| 边 | 2284 条，strength 3–5 占 76%；`related` 2018（88%） |
| 候选关系 | `sprout-candidate` 29 / `pollinate-candidate` 34 / `hydrogen-bond` 203（关系词已在，量被淹） |
| 全边发芽 | 任一关键词 1 跳触达 120–160 / 299（近完全图，无区分度） |
| 强边发芽（≥7） | `agent` 96、`记忆层` 55、`skill-optimization` 53；其余多数为 0 |

结论：**身份用错了对象（题头），派生面根本没有生成器**。本 spec 同时治这两条。

## 二、身份契约（spec 即契约）

### 2.1 三层分离

| 层 | 字段 | 由谁产生 | 可否变 |
|---|---|---|---|
| 身份 | `id`（序列号） | 入库分配，`e-<YYYYMMDD>-<序号>` | **永不变**；新内容＝新序列号 |
| 展示 | `title` | 从正文派生（首句/落档路径/摘要），失败兜底为 `id` | 可重算、可空、可丢 |
| 内容 | `content` + `keywords` + `variants` | 原料 + 抽取产物 | 不改写原料；修正＝新序列号 |

- `title` **不入任何键**：不进检索词面、不进关联键、不参与去重、不进 memo 卡片排序键（卡片显示 `title` 只是渲染）。
- `name` 列保留兼容，但**语义降为「序列号副本」**；旧库里 name=题头的 299 档在迁移时把原名搬进 `title`。

### 2.2 只追加

- 同内容重投：内容指纹（sha1 of 规范化正文）命中 → **不新建序列**，返回既有 id。
- 内容修订：新序列号入档；旧档写 `invalid_at` + `invalid_reason`（指新序列号），不覆盖、不物理删。
- 一个序列号一旦分配，`id` 与 `content` 均不再改写。

## 三、派生词生成器（本轮新增的缺环）

### 3.1 四个派生维

| 维 | 输入例 | 产物 |
|---|---|---|
| 繁简双形 | 意识神经 | 意识神经 / 意識神經（**两形都产，繁体优先展示**） |
| 粤语拆解 | 搞掂 / 边个跟 / 唔返来 | 词素 + 普通话对照：搞掂→搞定·完成；边个→谁；跟→处理·跟进 |
| 粤普对照 | 拎返嚟 | 拿回来 / 取回 |
| 缩写与词形 | aing / A/B / onnx-e5-small | 全称展开、连字符/空格变体、大小写归一 |

### 3.2 数据与边界

- 词典落 `data/lexicon/{zh-variant.json, yue-morph.json, yue-mandarin.json, abbr.json}`，纯本地、无外部 API、无网络调用。
- 生成器是**确定性纯函数**：同输入同输出，可缓存、可重算。
- 繁体是**首选展示形**（粤语与海外圈习惯）；简体与繁体在索引侧**等价**：查询任一形都能命中另一形的档。

### 3.3 查询侧归一

检索时对查询串同样做繁简归一与粤语拆解（同一生成器），否则「意識神經」打不到简体档、粤语口语打不到书面档。

## 四、索引面与关联面

### 4.1 入键字段

- 检索词面 = `content` + `keywords` + `variants`（`title` 不入键）。
- 向量面照旧吃正文（加 `keywords` 拼接），强度加权沿用 SPEC-1.8。

### 4.2 关联与发芽

- 进入发芽面的边：`sprout-candidate` / `pollinate-candidate` / `hydrogen-bond` **且 strength ≥ 7**。
- 泛 `related`（当前 88%）只作背景层，**不入发芽、不进检索排序加分**。
- 发芽度（每关键词可复算）：
  `sprout(kw) = |{实体: 经 strength≥7 边可达}|`，另报 `variants(kw)` = 由该词派生的词数。
- 「知识链长度」= 全部关键词按 sprout 排序后的分布，不看实体总数。

## 五、迁移（旧 299 档）

1. 旧 `name`（题头）→ `title`；`id` 保留原 slug 作为该档序列号的**别名**（新增 `alias` 列），不重写、不重排。
2. 旧 `id` 若已被外部引用（links 两端、memo、测试），一律按别名解析到现有序列号。
3. 新入库走新规（`e-...` 序列号 + 指纹去重）。
4. 迁移脚本必须：可重跑（幂等）、先备份、跑完对账（档数、links 端点数不变）。

## 六、Acceptance Criteria

| # | 判据 | 检验方式 |
|---|---|---|
| AC-1 | 表头不加工 | 新入库 `name`＝序列号；`title` 由正文派生；改正文→新序列号、`title` 随之变、`id` 不变 |
| AC-2 | 只追加 | 同内容重投不新建（指纹命中返既有 id）；修订走新序列号 + 旧档 `invalid_at` |
| AC-3 | 繁简双形 | 入库「意识神经」产出繁体变体；查询「意識神經」命中简体档（双向各一例） |
| AC-4 | 粤语拆解 | 「搞掂」「边个跟」「唔返来」各产出词素+普通话对照 |
| AC-5 | 派生词入键 | `title` 不进检索词面（行为：伪造 title 不影响命中顺序）；`variants` 进词面 |
| AC-6 | 发芽只走强边 | strength<7 的 `related` 不计入 sprout；三条候选关系可计 |
| AC-7 | 发芽度可复算 | 同一库、同一关键词两次计算相等；报告含 sprout 与 variants 两列 |
| AC-8 | 迁移幂等 | 迁移脚本连跑两趟，档数/links 端点数/别名映射不变 |
| AC-9 | 纯本地 | 生成器与词典无网络调用（源码扫描 + 断网跑通） |

## 七、Non-Goals

- 不做机器翻译（只做词典级拆解与对照，不做整句翻译）。
- 不引入外部词典服务；词典体积与条目数本期不设上限，按需增补。
- 不改 9 段强度语义、不改三轴列（0.1 契约不动）。
- 不做 UI；`title` 只服务 memo 与对照单渲染。

## 八、落地顺序（建议）

1. 生成器 + 词典（纯函数 + 单测：AC-3/4/9）
2. 序列号身份与指纹去重（AC-1/2）
3. 检索/关联入键改造（AC-5/6）
4. 发芽度报告工具（AC-7）
5. 旧库迁移（AC-8），迁移后再重跑 24 条后端对照单

## 九、风险

- `agent` 这类超高频词会在强边下成为新 hub（现读数 96 实体）→ 发芽报告需带 hub 警戒线，超线只报不扩。
- 粤语词典覆盖不足时，拆解会退化为整词命中；报告需同时给「拆解成功率」，不装作全覆盖。
