# SPEC-7.1 · 序列号身份 × 派生词发芽面

> 定调（2026-11-17）：知识进 aing 后 **表头只是序列号，aing 不处理它**；全部加工对象是正文。
> 新内容另有序列号（只追加，不改写）。关联由内容产生：**关键词能长出多少派生词、关联得越多，就是知识链**。
> 另两条硬要求：**粤语本身可以拆**（词素级）；**繁体是粤语最常用形、也是海外圈主用形**——生成器必须同时产繁体。

## 〇、定位：aing 的代谢是**关键词繁育代谢**

不是「文档归档 + 向量近邻」，而是：**关键词在库中繁育出派生词，派生词再关联，关联连成链**。

| 命题 | 含义 | 落到本 spec |
|---|---|---|
| 代谢单位是关键词 | 加工对象是正文里的词与词间关系，不是整篇文档的相似度 | §三 生成器、§四 发芽面 |
| 繁简是基本功 | 繁简互通不是加分项，是底线；做不到就等于半个库失联 | §三.1 繁简双形、§三.3 查询归一 |
| 西语不是难度 | 拉丁词按词形/连字符/大小写确定性切分即可，不涉及翻译 | §三.1 缩写与词形 |
| 用户表达即查询 | 用户说了什么，agent 直接读库就该知道怎么答——不需要二次翻译或改写 | §4.4 抽库装配 |
| 时间是两道 | **原始时间**（源头何时产生）+ **关联时间**（链何时长出来），二者都保留 | §4.5 时间轴 |
| 会话入库＝多源头 | 每条会话是一个「开头不同」的源头；agent 一次抽库即得四件 | §4.4、§4.5 |

**验收的最终口径**：给一句用户表达，aing 抽出 `源头 + 派生 + 关联 + 链` 四件并能按时间序讲清——够帮到用户，就算这条代谢成立。别的指标都是过程量。


## 一、现状读数（2026-11-17 在实库副本上量）

| 项 | 值 |
|---|---|
| 实体 | 299 活跃 / 320 全库，id = 名字 slug（身份＝题头） |
| 关键词 | 92 个，无死端；但 72 个在强边下**一条外扩边都没有** |
| 边 | 2284 条，strength 3–5 占 76%；`related` 2018（88%） |
| 候选关系 | `sprout-candidate` 29 / `pollinate-candidate` 34 / `hydrogen-bond` 203（关系词已在，量被淹） |
| 全边发芽 | 任一关键词 1 跳触达 120–160 / 299（近完全图，无区分度） |
| 强边发芽（≥7） | `agent` 96、`记忆层` 55、`skill-optimization` 53；其余多数为 0 |

结论：**身份用错了对象（题头），派生面根本没有生成器**。本 spec 同时治这两条。

## 二、身份契约（spec 即契约）

### 2.1 三层分离

| 层 | 字段 | 由谁产生 | 可否变 |
|---|---|---|---|
| 身份 | `id`（序列号） | 入库分配，`e-<YYYYMMDD>-<序号>` | **永不变**；新内容＝新序列号 |
| 展示 | `title` | 从正文派生（首句/落档路径/摘要），失败兜底为 `id` | 可重算、可空、可丢 |
| 内容 | `content` + `keywords` + `variants` | 原料 + 抽取产物 | 不改写原料；修正＝新序列号 |

- `title` **不入任何键**：不进检索词面、不进关联键、不参与去重、不进 memo 卡片排序键（卡片显示 `title` 只是渲染）。
- `name` 列保留兼容，但**语义降为「序列号副本」**；旧库里 name=题头的 299 档在迁移时把原名搬进 `title`。

### 2.2 只追加

- 同内容重投：内容指纹（sha1 of 规范化正文）命中 → **不新建序列**，返回既有 id。
- 内容修订：新序列号入档；旧档写 `invalid_at` + `invalid_reason`（指新序列号），不覆盖、不物理删。
- 一个序列号一旦分配，`id` 与 `content` 均不再改写。

## 三、派生词生成器（本轮新增的缺环）

### 3.1 四个派生维

| 维 | 输入例 | 产物 |
|---|---|---|
| 繁简双形 | 意识神经 | 意识神经 / 意識神經（**两形都产，繁体优先展示**） |
| 粤语拆解 | 搞掂 / 边个跟 / 唔返来 | 词素 + 普通话对照：搞掂→搞定·完成；边个→谁；跟→处理·跟进 |
| 粤普对照 | 拎返嚟 | 拿回来 / 取回 |
| 缩写与词形 | aing / A/B / onnx-e5-small | 全称展开、连字符/空格变体、大小写归一 |

### 3.2 数据与边界

- 词典落 `data/lexicon/{zh-variant.json, yue-morph.json, yue-mandarin.json, abbr.json}`，纯本地、无外部 API、无网络调用。
- 生成器是**确定性纯函数**：同输入同输出，可缓存、可重算。
- 繁体是**首选展示形**（粤语与海外圈习惯）；简体与繁体在索引侧**等价**：查询任一形都能命中另一形的档。

### 3.3 查询侧归一

检索时对查询串同样做繁简归一与粤语拆解（同一生成器），否则「意識神經」打不到简体档、粤语口语打不到书面档。

## 四、索引面与关联面

### 4.1 入键字段

- 检索词面 = `content` + `keywords` + `variants`（`title` 不入键）。
- 向量面照旧吃正文（加 `keywords` 拼接），强度加权沿用 SPEC-1.8。

### 4.2 关联与发芽

- 进入发芽面的边：`sprout-candidate` / `pollinate-candidate` / `hydrogen-bond` **且 strength ≥ 7**。
- 泛 `related`（当前 88%）只作背景层，**不入发芽、不进检索排序加分**。
- 发芽度（每关键词可复算）：
  `sprout(kw) = |{实体: 经 strength≥7 边可达}|`，另报 `variants(kw)` = 由该词派生的词数。
- 「知识链长度」= 全部关键词按 sprout 排序后的分布，不看实体总数。

### 4.3 抽库装配四件（回答的最小单位）

一句用户表达进来，抽库必得四件，缺一件就算没抽全：

| 件 | 取处 | 说明 |
|---|---|---|
| 源头 | 会话实体（`type=Conversation`）的序列号 + 原始时间 | 哪个会话、何时产生；不同会话就是不同源头，各自开头不同 |
| 派生 | `variants`（繁简/粤拆/粤普/缩写） | 同一意思的其它写法，供命中与解释 |
| 关联 | strength≥7 或三类候选关系连到的实体 | 谁和谁有关、凭什么（evidence） |
| 链 | 从关键词出发沿强边走出的有序序列 | 按 §4.4 的时间轴讲，不是一堆无序卡片 |

### 4.4 时间轴：原始时间 + 关联时间

- **原始时间**：`entities.created_at`（源头产生时刻），随内容走，永不改。
- **关联时间**：`links.created_at`（链何时长出来），只追加。
- 讲述顺序 = 先按原始时间讲源头，再按关联时间讲链怎么长出来；**不许重排成「看起来最相关」的顺序冒充时间序**。
- 同一事实被新内容修正：新序列号带新原始时间，旧档 `invalid_at` 保留，链上能看出「何时改口」。


## 五、代谢流程对位：关键词每一步由谁处理

> 口径：每一步只回答一个问题——**它管关键词的哪一环**；没有归属的步骤说明它不碰词（只报读数），不硬塞。

| 步 | 管的环 | 现状 | 本 spec 要补的动作 |
|---|---|---|---|
| `ingest`（会话入库） | **源头登记** | 会话实体 + `created_at` + WAL | 分配序列号、内容指纹去重、每条会话标为独立源头 |
| `compile` | 正文规范化 | raw→wiki 落 `content`/`tags` | 保留原字形并记 `original_script`（繁/简/粤），不做有损归一 |
| `distill` | **关键词抽取 + 强度** | tags 由上游给定 | 抽词器：CJK 双字 + 拉丁词 + **派生词**；强度映射 9 段 |
| `distill-points` | 论述单元绑定 | 区间捕获蒸馏点 | 每个点绑关键词/派生词，供「链」讲述时定位 |
| `trajectory` | 源头时间序 | 会话/代谢轨迹 | 与 `entities.created_at` 对齐，作为原始时间的旁证 |
| `insight-extract` | 候选洞察 | raw 链候选实体 | 洞察稿带关键词，但不进主索引 |
| `link-sync` | 边一致性 | 双链边同步 | 边必须带 relation 类型（候选/确认/泛related） |
| `vector` | 向量面 | 正文向量 | 拼入 `variants`；`title` 不拼（§2.1） |
| `sprout` | **发芽** | CJK 双字重叠 ≥2 + 共享标签 + 共同邻居 | 重叠判定改用派生词集合（繁简/粤拆/粤普/缩写），候选边门槛 strength≥7 |
| `pollinate` | 跨域授粉 | 跨域配对 | 用派生词做跨域扩展（同义不同领域） |
| `hub-trim` | **泛词抑制** | 按度数 cap | 按词频/PMI 修正，防 `agent` 这类词长成新 hub |
| `field-maintain` | 场域动作 | 维护动作 | 词级维护：同义派生合并、错拆回滚 |
| `compress` | 压缩 | 按衰减压缩 | 压缩后关键词与派生词必须保留（不得只剩摘要） |
| `recycle` | 回炉 | 重跑链 | 重抽词（老档补派生词） |
| `kespi` | 质量读数 | 八维 | 词级活性：被 `access_hits` 消费过的词算活 |
| `prune` | 退役 | 三轴判据 | 词退役可逆；派生词随实体退役 |
| `conservation` | 守恒 | 链守恒 | 词-边守恒：新增派生词必须能追溯到源实体 |

**读法**：`ingest → compile → distill` 是「源头 → 正文 → 词」的生产段；`vector / sprout / pollinate / hub-trim` 是「词 → 关联」的繁育段；`kespi / prune / conservation` 是「活/退/守」的收口段。三段各管一事，不跨界。

## 六、外部对标与优化方向（结论：全部本地化，不引在线服务）

| 主题 | 外部做法（2023–2025 共识） | 本项目取舍 |
|---|---|---|
| 关键词抽取 | 统计式（YAKE/RAKE）最快且跨语种稳定；图式（TextRank）长文退化；KeyBERT 最准但慢、需模型 | 采用**规则 + 统计**（词频、共现、位置），不引模型；已有 CJK 双字切分作为基座 |
| 共现建边 | PMI / NPMI 作边权，正 PMI 才留边，按节点 top-k 剪枝；NPMI 缓解高频词偏差 | 把 PMI/NPMI 映射到 9 段强度，**替代现在 88% 的泛 `related`（strength 3–5）** |
| 查询扩展 | 保留原查询并行检索、原查询加权更高；扩展 ≤3 条、权重递减、阈值过滤；只对短查询/模糊查询触发 | 采纳为 §三.3 的实现约束，写进 AC |
| 繁简转换 | OpenCC 是事实标准（`s2t` / `t2s` / `s2hk`）；有纯 JS 实现（opencc-js）与内联词典 | 采其**词典数据**离线打包（不引原生依赖）；HK 变体正对粤语与海外圈 |
| 粤语分词 | pycantonese 用 rime-cantonese 词表；words.hk 5.3 万条；HKCanCor 约 20 万词（CC BY 4.0） | 取词表做**词素切分**与粤普对照；许可与出处随词典文件登记 |
| 语义词典 | 同义词词林（约 7.7 万词、五级树）、HowNet/OpenHowNet（义原分解） | 用于派生**同义/上下位**，离线打包；只做词级，不做句译 |

**两条硬约束**（沿用本仓既有口径）：生成器与词典纯本地、无网络、无 GPU；所有外部词典的许可与出处登记在 `data/lexicon/README.md`。

## 七、迁移（旧 299 档）

1. 旧 `name`（题头）→ `title`；`id` 保留原 slug 作为该档序列号的**别名**（新增 `alias` 列），不重写、不重排。
2. 旧 `id` 若已被外部引用（links 两端、memo、测试），一律按别名解析到现有序列号。
3. 新入库走新规（`e-...` 序列号 + 指纹去重）。
4. 迁移脚本必须：可重跑（幂等）、先备份、跑完对账（档数、links 端点数不变）。

## 八、Acceptance Criteria

| # | 判据 | 检验方式 |
|---|---|---|
| AC-1 | 表头不加工 | 新入库 `name`＝序列号；`title` 由正文派生；改正文→新序列号、`title` 随之变、`id` 不变 |
| AC-2 | 只追加 | 同内容重投不新建（指纹命中返既有 id）；修订走新序列号 + 旧档 `invalid_at` |
| AC-3 | 繁简双形 | 入库「意识神经」产出繁体变体；查询「意識神經」命中简体档（双向各一例） |
| AC-4 | 粤语拆解 | 「搞掂」「边个跟」「唔返来」各产出词素+普通话对照 |
| AC-5 | 派生词入键 | `title` 不进检索词面（行为：伪造 title 不影响命中顺序）；`variants` 进词面 |
| AC-6 | 发芽只走强边 | strength<7 的 `related` 不计入 sprout；三条候选关系可计 |
| AC-7 | 发芽度可复算 | 同一库、同一关键词两次计算相等；报告含 sprout 与 variants 两列 |
| AC-8 | 迁移幂等 | 迁移脚本连跑两趟，档数/links 端点数/别名映射不变 |
| AC-9 | 纯本地 | 生成器与词典无网络调用（源码扫描 + 断网跑通） |
| AC-10 | 抽库四件齐 | 给一句用户表达，输出含源头/派生/关联/链四件；缺任一件即红 |
| AC-11 | 时间序可复现 | 讲述顺序 = 源头按 `created_at`、链按 `links.created_at`；同库两次抽取顺序一致，不许按相关度重排冒充 |
| AC-12 | 扩展有上限 | 查询扩展 ≤3 条、去重、权重递减；原查询保留并加权更高；短/模糊查询才触发 |
| AC-13 | 词典可追溯 | 每个词典文件登记出处与许可；抽词器对同输入同输出（确定性） |

## 九、Non-Goals

- 不做机器翻译（只做词典级拆解与对照，不做整句翻译）。
- 不引入外部词典服务；词典体积与条目数本期不设上限，按需增补。
- 不改 9 段强度语义、不改三轴列（0.1 契约不动）。
- 不做 UI；`title` 只服务 memo 与对照单渲染。

## 十、落地顺序（建议）

1. 生成器 + 词典（纯函数 + 单测：AC-3/4/9/13）
2. 序列号身份与指纹去重（AC-1/2）
3. 检索/关联入键改造 + 扩展上限（AC-5/6/12）
4. 抽库四件装配 + 时间轴（AC-10/11）——这是「用户表达 → 直接读库就知如何答」的最小闭环
5. 发芽度报告工具 + PMI 强度映射（AC-7）
6. 旧库迁移（AC-8），迁移后再重跑 24 条后端对照单

## 十一、风险

- `agent` 这类超高频词会在强边下成为新 hub（现读数 96 实体）→ 发芽报告需带 hub 警戒线，超线只报不扩。
- 粤语词典覆盖不足时，拆解会退化为整词命中；报告需同时给「拆解成功率」，不装作全覆盖。
