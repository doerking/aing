# SPEC-0.5 · 内外蜂群接线 + 内蜂群部署重设

> M0 纯设计零码。改写宪法遵守：**本 spec 不出现任何第三方名称、不泄露真实路径**，全部用中性描述 / 语义占位符。
> 两套蜂群分属两层，**设计本意不桥接**（麦当华 2026-11-03 口述，此处承其结构不点名出处）。改写后内蜂群**脱离第三方运行时载体，按 aing-v2 自洽部署**。

---

## 一、目标

钉死改写后 aing-v2 的蜂群双层结构：
- **内蜂群**（自维护）：脱离第三方载体，**随 aing-v2 包自洽部署**，触发源对齐新架构读数面
- **外蜂群**（对外派工）：载体在宿主侧，aing-v2 只做链路保障端，接新事件面
- **铁律**：两套不桥接，互不知晓对方存在

## 二、内蜂群（自维护）· 部署重设

### 2.1 改写前 vs 改写后

| 项 | 改写前 | 改写后（aing-v2） |
|---|---|---|
| 载体 | 依赖第三方技能运行时面探测 | **随 aing-v2 包自带**（`<skill-assets>/`），自洽部署，不依赖任何外部运行时 |
| 触发源 | 健康读数（旧 metabolism/memo 面） | **新架构读数面**：KESPI 八维 + verify 门禁红绿 + meko_cycles 健康 + gaps/selfImprovement |
| 规模 | 固定 5 角色 | 固定 5 角色（保留，职能映射到新架构） |
| 探测 | 靠外部面 query tags | **aing-v2 内部 query 面**（不依赖第三方探测） |

### 2.2 五角色职能映射（保留结构，对接新架构）

| 角色 | 职能（不变） | 触发源对接（改写后） |
|---|---|---|
| 健康巡检 | 读 selfAssessment 六属性 | 新 briefing（意识层 self-state 只读档） |
| 验收 | verify 门禁 | aing-v2 verify-deploy ALL GREEN 面 |
| 缺口修复 | gaps 派单 | 新 KESPI gaps + meko_cycles failed |
| 自我提升 | selfImprovement 提案 | 四门回滚链 + 成长层 |
| 对抗审查 | 独立挑刺，揾计划缺陷 | 每期 adversarial challenge（工程规范 R3） |

### 2.3 自洽部署要点（宪法③核心）

- **载体自洽**：内蜂群五角色说明书 + workflow + 绑定文件全部随 `aing-v2/<skill-assets>/` 走，**不装、不依赖任何第三方运行时面**——部署 aing-v2 即内蜂群就位。
- **探测自洽**：健康读数从 aing-v2 内部取（briefing / verify / query 面），**不经第三方探测通道**。
- **派单自洽**：健康驱动派单 + agent 手动，派单账走 aing-v2 意识层事件面（SPEC-0.2 ④ + meko_cycles）。

## 三、外蜂群（对外派工）· 保障端接线

### 3.1 边界（不变，宪法①改写表述）

- 外蜂群载体在**宿主侧运行时面**（不点名任何第三方平台，统一称「宿主运行时面」）。
- aing-v2 对外蜂群**只做链路与考核保障，不做编组指挥**：编组（点→单元→班→营）在宿主侧。

### 3.2 aing-v2 保障端三件（接新事件面）

| 保障 | 功能 | 改写后接哪 |
|---|---|---|
| 轨迹留痕 | 派工单带身份/落点，唔返嚟都落盘 | 意识层事件面（neural 事件 + decision lineage） |
| 心跳/链路面 | 批次接力、线断不死 | meko_cycles（scheduleCycle 编排心跳） |
| 归因账 + KESPI 考核 | 收全部归因、考效率 | KESPI 八维 + trajectory-store |

## 四、两套不桥接（铁律，改写后仍成立）

- 内蜂群自维护团队**不装进任何通用运行时面**，外蜂群派工面**探不到它**——不构成缺口（改写后由 aing-v2 内部面取代外部探测，缺口语义消失）。
- 唯一共享：运行时投票补对抗检查（导链蜂群自身质量），**与派工边界无关**。

## 五、Acceptance Criteria（可客观检验，隔离假院真跑）

| # | 判据 | 检验方式 |
|---|---|---|
| AC-1 | 内蜂群随包自洽 | 假院只装 aing-v2 包 → `<skill-assets>/` 下内蜂群五角色说明书齐全，不依赖任何外部运行时即可被 aing-v2 内部面加载 |
| AC-2 | 触发源接新读数面 | 造一个 verify 红 / KESPI 缺口 → 内蜂群健康巡检角色能从新读数面取到该信号并派单 |
| AC-3 | 探测不经第三方 | 内蜂群健康读数全从 aing-v2 内部 briefing/query 取，关闭外部运行时面后内蜂群仍能跑（证明不依赖） |
| AC-4 | 外蜂群保障端接线 | 造一条派工事件 → 轨迹留痕进 decision lineage、心跳进 meko_cycles、归因进 trajectory-store，三件各归其位 |
| AC-5 | 两套不桥接 | 内蜂群派单不触发外蜂群编组；外蜂群探测不到内蜂群（双向证不桥接） |
| AC-6 | 宪法合规 | 本 spec 及实现全文无第三方名称、无真实路径泄露（grep 第三方名 = 0） |

## 六、Non-Goals

- **不改外蜂群编组学说**——点线面/四通道/9段谱系在宿主侧，本 spec 只管 aing-v2 保障端接线。
- **不桥接两套**——铁律不改。
- **不点名第三方**——宪法①，宿主运行时面统一中性称「宿主运行时面」。
- **不实现**——M0 零码，内蜂群部署落地属 M3（技能资产迁移 + 意识层接线），外蜂群保障端属 M2/M3 事件面接线。

## 七、依赖

- **上游**：SPEC-0.1（三表）、SPEC-0.2（意识层事件面）、SWARM 设定（结构来源）
- **被依赖**：M2（外蜂群保障端接事件面）、M3（内蜂群技能资产迁移 + 部署重设落地、意识层接线）
