# SPEC-6.25 · 扫单按维配额

> **一句话**：全局抢 20 个位，分数天然偏低的那一维（kd=0、ka=0.2）永远赢——kq 有 56 个实体低于阈值，却一张单都开不出来。

## 一、病

- `MAX_TICKETS = 20` 对全维共用，候选按分数升序取前 20。
- kd 常为 0、ka 常为 0.2~0.3，kq 最低也有 0.23——**kq 永远排在后面**。
- 真实副本实测：14 轮代谢、20 张单里 kd 8 + ka 12，kq 0 张。
- 后果：质量维（kq）在自优化里实际是失明的，`kd/ka` 决定所有注意力。

## 二、改法

```js
const DIM_QUOTA = { kq: 5, ka: 5, kr: 5, kc: 5, kd: 8, overall: 3 };
```

- 逐条按维计数，取到该维上限就跳过；**总上限仍是硬顶**（`maxTickets`）。
- `opts.quota` 可覆盖单维（测试与运维用）。
- 排序不变：同一维内仍按分数升序——配额限制的是「谁有席位」，不是「谁先上」。

## 三、真库副本对照

| 项 | 修前 | 修后 |
|---|---|---|
| kq 单 | 0 | 5 |
| ka 单 | 12 | 5 |
| kd 单 | 8 | 8 |
| overall 单 | 0 | 3 |
| 合计 | 20 | 21（含 1 张已收单） |

配额后 P2 半寄生一轮仍跑通：kq 0.2393 → 0.85，`verified/accepted`。

## 四、Acceptance Criteria

| # | 判据 |
|---|---|
| AC-1 | 10 个 kq 低实体 → 默认只开 5 张 |
| AC-2 | kq/ka 各 10 个 → 各 5，互不挤占 |
| AC-3 | `opts.quota` 覆盖生效（kq:2 → 2 张） |
| AC-4 | 总上限仍优先（maxTickets:3 → 3 张） |
| AC-5 | 配额内低分优先（取分数最低的 5 个） |
| AC-6 | 无重复 `(entity, dim)`，且不超总上限 |

## 五、Non-Goals

- 不改各维阈值（`DIM_RULES.below`）。
- 不做动态配额（按积压比例伸缩）——先固定，观察一轮再说。

## 六、仍开着的

1. 配额是固定值，库很小时（如只有 3 个 kq 低）其余名额不会让给别的维（当前实现允许，因为循环继续走到其他维；总上限 20 仍填得满）。
2. 维护轮之外 L3 仍不执行——这是 6.8 §三「默认不下药」的设计，不是缺陷；要用得显式开维护轮。
