# SPEC-6.35 · 段有效阈值滑动

> **一句话**：阈值钉死 20 字，外部件就会刚好写 20 字贴线过关。基准仍是 20，但每个实体拿到 15 或 25——写够 25 才稳。

## 一、口径

```js
base = 20, jitter = 5
sectionThreshold(entityId) = base + (hash(entityId) 奇偶 ? +5 : -5)   // 15 或 25
```

- **随机性来源**：实体 id 的稳定散列，不是每次调用重新掷。
- **同实体跨轮恒定**：同一实体今天验收是 25，明天还是 25——否则 kq 自己跳变，验收变成掷骰子。
- **不同实体各半**：约一半实体 15、一半 25，形成横向分布，逼着接单方按 25 写。
- **无 entityId 时退回 20**：纯函数默认口径不变，老调用方无感。

## 二、代价与边界

- kq 对同一实体仍可复现（散列确定），审计可复算阈值。
- 贴线 20 字的段在一半实体上作废——这正是要的效果。
- 只影响六段叙事的段有效性判定；非叙事实体零影响。

## 三、Acceptance Criteria

| # | 判据 |
|---|---|
| AC-1 | `sectionThreshold(id)` 只返回 15 或 25，同 id 恒定 |
| AC-2 | 不同 id 两种阈值都出现（不是全 15 或全 25） |
| AC-3 | 无 entityId → 退回 20（老口径不变） |
| AC-4 | 17 字的段：15 档实体算有效、25 档实体算无效 |
| AC-5 | 同实体连跑两轮 kq 一致（不跳变） |
| AC-6 | 非叙事实体读数不变（回归） |

## 四、仍开着的

1. 15/25 两档是否太粗（±5 步进）——若要 13~27 连续散列，是改一行的事，等分布数据。
2. 阈值不进回单；接单方不知道本实体走哪档，只能按最严（25）写——这是有意的。
3. 必填段是否随能力面浮动（6.34 遗留）仍未决。
