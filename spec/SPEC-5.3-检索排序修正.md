# SPEC-5.3 · 检索排序修正（文档投喂实测驱动）

> 实测（2026-11-16，18 份真实工作区文档、36 实体隔离库）：投喂管道全通，但检索答非所问。
> 三条结构性修正：**简繁归一**（繁体正文能被简体查询命中）、**双字权重 ×2**、**双链去重**。
> 不吹的地方写清楚：这批查询里 top-1 仍未到「可信」水平（§七），词面通道与评测集是下一步，判据不在这里松。

---

## 一、目标

1. 默认向量后端由 `hash-64` 升为 `hash-64w2`：先 t2s 简繁归一再切词；CJK 双字与拉丁词权重 2，单字权重 1。
2. `hash-64` 保留为内置后端，可显式切换（不折叠、权重全 1，**逐位等于 SPEC-1.8**），供对照与回退。
3. 检索结果按**双链基名**去重：`wiki-X` 与 `X` 同一份知识只留一条，`k` 按去重后条数计。

## 二、行为（spec 即契约）

### 2.1 默认模型 `hash-64w2`

- **简繁归一**：向量化前逐字折叠（繁体 → 简体）。字表 `src/t2s-chars.json`，3553 条单字映射，来源 OpenCC t2s 数据（Apache-2.0），本地生成后随包。
  - 只折**单字**，不做词组转换；简体字原样返回。
  - 只在字符层面等价，不改语义；`hash-64` 旧口径**不折叠**。
- **权重**：CJK 单字 1、CJK 双字 2、拉丁词 2；带符号累加进 64 桶，L2 归一。
- `MODEL = 'hash-64w2'`，`DIM = 64`；`listBackends()` 同时列出 `hash-64`（内置，旧口径）与 `hash-64w2`（内置，默认）。
- 两个内置后端都不可被 `registerBackend` 覆盖。

### 2.2 双链去重

- 基名 `base = id.replace(/^wiki-/, '')`；同 base 只保留分最高的一条。
- 分数相同：保留非 `wiki-` 那条（raw 是真源，wiki 是镜像）。
- `k` 约束在去重之后；返回条数 ≤ k。
- 命中对象新增 `base` 字段（可加不可断，旧字段不动）。

### 2.3 不变的

- 排序分仍为 `cosine × (0.5 + 0.5 × strength / 9)`。
- 跨后端过滤（`model` + `dim`）不变；换默认后端后 `vectorStep` 全量重建。
- 铁律不变：不碰 `last_access` / `tolaria_strength` / `invalid_at`；无物理删。

## 三、Acceptance Criteria

| # | 判据 | 检验方式 |
|---|---|---|
| AC-1 | 默认已升 | `resolveBackend().name === 'hash-64w2'`；`MODEL` 同；`listBackends` 含两个内置；建向量记新 model |
| AC-2 | 旧口径可切且逐位不变 | `vectorOf(text,{backend:'hash-64'})` == SPEC-1.8 快照 |
| AC-3 | 简繁归一 | 正文写「双相循环」、查询写「双相循环」→ 该文档排第一 |
| AC-4 | 双字权重 | 同查询下，含「双相循环」双字者排在只有散字者之前 |
| AC-5 | 双链去重 | raw + wiki 镜像同内容 → 结果只出一条，且优先 raw |
| AC-6 | k 按去重后计 | `k=2` 返回两条不同 base |
| AC-7 | 强度加权不变 | 同文同查询，9 段排 3 段前 |
| AC-8 | 内置不可覆盖 + 铁律 | 覆盖两个内置名均抛错；`last_access` 不变；源码无 `DELETE FROM` |

## 四、Non-Goals

- 不做词面/BM25 通道、不做语义模型、不改表结构、不改强度加权公式。
- 不做词组级简繁转换（「软件/軟體」这类地区用词差异不在本任务）。
- 不调评测集、不按 8 条查询调参。

## 五、契约

- `vectorOf(text, opts)` / `vectorStep(store, opts)` / `search(store, q, opts)` 签名不变。
- `MODEL` 导出值改为 `hash-64w2`；`DIM` 仍 64；新增导出 `fold`、`rawTokens`。
- `search` 返回项新增 `base`；`k` 语义改为「去重后条数」。

## 六、依赖

- 上游：SPEC-1.8（原口径）、SPEC-5.1（后端注册与混用防护）
- 数据：`src/t2s-chars.json`（OpenCC t2s，Apache-2.0，随包）
- 影响：`src/predict.js`、编排器 vector 组件（走默认，无需改）
- 迁移：换默认后整库重建向量（checksum 同、model 异 → 全量 rebuilt）

## 七、实测证据与仍未解决的部分

同批 18 份文档、8 条真查询（去重后，单条 top-1 命中）：

| 口径 | top-1 命中 | MRR@3 |
|---|---|---|
| `hash-64`（旧默认，不折叠、权重 1） | 2/8 | 0.417 |
| `hash-64w2`（本任务） | 3/8 | 0.542 |
| 词面 IDF 通道（未落地） | 4/8 | 0.604 |
| 混合融合（未落地） | 4/8 | 0.646 |

- 8 条查询的差异在 ±1 量级，**不足以决定架构**；结论只当方向证据，不作承诺。
- 仍未解决：`hash-64` 家族靠 64 桶哈希，术语权重被碰撞吃掉；真正的下一步是**词面通道（IDF/BM25）** 与**冻结评测集**（≥50 条，粤语 ≥15 条），按 `docs/Engineering/EMBEDDING-BENCH-2026-11-16.md` 的口径来判。
- 换不换默认、用不用词面通道，仍按「使用者自己语料复核」那条规矩走。
