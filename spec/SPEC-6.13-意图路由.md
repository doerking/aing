# SPEC-6.13 · 意图路由（规则分类 + 权重分流）

> 状态：实装（2026-11-17）
> 上游：SPEC-6.3（三路融合与修订 B 权重）、SPEC-5.9（语义缺省）
> 定位：同一个检索器要应付三种问法——**找东西**（id / 文件名 / 「边份」）、**回忆经过**（「上次」「结果如何」）、**解释概念**（「是什么」「点解」）。它们该给的通道不同；用一套权重全接，必然顾此失彼。

---

## 一、为什么单列一件

外部调研的共识是「flat 检索不够，查询要按意图路由」；但本件不引入模型，只用**可解释的规则**（关键词 / 句式），并且**只在证据清楚时改权重**——不清楚就当「一般」，维持现状，不退步。

## 二、分类（`src/intent.js`，纯函数）

`classifyIntent(query)` → `{ intent, weights, rerank, hits }`

| 意图 | 触发（任一） | 典型问法 |
|---|---|---|
| `lookup` | 序列号/id 形态（`e-YYYYMMDD-NNNN`、含连字符的拉丁标识符）、「边份 / 哪个文件 / 落在哪 / 喺边」 | 「三分编组草案落在哪个文件」 |
| `recall` | 「上次 / 之前 / 讲过 / 复盘 / 结果 / 搞掂 / 郁过 / last / previous」 | 「外派第一单搞掂未」 |
| `explain` | 「是什么 / 什么是 / 点解 / 为什么 / 怎么 / 点样 / 如何 / how / why」 | 「技能和知识怎么互相代谢」 |
| `general` | 以上都不命中 | 「安全债还剩几项没决策」 |

优先级：`lookup > recall > explain`（问「边份文件放咗喺边」时找物的诉求压过回忆）。
`hits` 记录命中的规则词，供解释；分类不依赖词库之外的数据。

## 三、分流（`retrieval.search` 内）

- 调用方显式给了 `opts.weights` / `opts.rerank` 时，**以调用方为准**，路由不介入（测试与调参口径不变）。
- `opts.intentRouting === false` 可整件关掉（对照用）。
- 各意图的缺省（覆盖单层，未列项沿用 SPEC-6.3 修订 B）：

| 意图 | vector | lexical | name | rerank.recency |
|---|---|---|---|---|
| `general` | 0.80 | 0.05 | 0.15 | 0.10 |
| `lookup` | 0.55 | 0.10 | 0.35 | 0.10 |
| `recall` | 0.80 | 0.05 | 0.15 | 0.25 |
| `explain` | 0.85 | 0.05 | 0.10 | 0.05 |

- 返回 `meta.intent = { intent, hits }`，任何一次检索都能说明「为什么用这套权重」。
- 铁律不变：只读、不写 `last_access`、不物理删。

## 四、验收（`test/test-6.13-intent-routing.js`）

| AC | 断言 |
|---|---|
| AC-1 | 分类表：查物 / 回忆 / 解释 / 一般 各 ≥2 条手写问句分对，且 `hits` 非空（可解释） |
| AC-2 | 优先级：同时出现「边份」与「记得」时判 `lookup` |
| AC-3 | lookup 把名称通道抬上去：id 精确命中排在正文相关条目前 |
| AC-4 | recall 提高新鲜度权重：同内容新旧两条，新的排前 |
| AC-5 | 显式 `opts.weights` 压过路由；`intentRouting:false` 时恢复缺省权重 |
| AC-6 | 一般查询的缺省权重与 SPEC-6.3 修订 B 逐项一致（不退步） |

## 五、Non-Goals

- 不引入模型分类器、不做多意图混合打分。
- 不改向量/词面/名称三路的计算方式（只调权重）。
- 不按意图改 `k`、不改去重、不改慢回忆触发阈值。
- 不在本件调意图表之外的数值：没有证据的意图一律落 `general`。

## 六、已知边界

- 规则分类对反讽、隐喻问句无效；落 `general` 即退回现状，不是错误答案。
- 权重表由设计给出，非冻结集扫描产物（冻结集无意图标签）；效果以「一般查询不退步」+ 定向用例为准，真实语料复核仍走 SPEC-5.6 对照单。
