# 进化回路：回炉与学习梯度

## 设计哲学

知识系统没有失败，只有未发芽。压缩、剪枝、裁决失败都不是终点状态，
而是物质转化：矛盾体剪断成芥子，芥子回炉成元知识微粒，微粒再发芽。
本蓝图补全双脑架构缺失的最后一环——进化回路。

## 回炉闭环（Recycle Loop）

### 两阶段动作

```
阶段1 回炉：未消费芥子 → 元知识微粒 (mz-<original_id>)
            内容 = 压缩摘要（密度最高的知识形态）
            血统 = recycled_from 链接回指原体
            防循环 = seed 标记已消费，每粒最多回炉一次

阶段2 入土：精华已转世的压缩残壳 → 归档
            raw/wiki 文件移入 pruned/（可溯源）
            DB 清引用（防下轮编译复活）
```

### 数据契约

| 约定 | 内容 |
|------|------|
| seed id | `seed-<entity_id>`，确定性可复算 |
| 消费标记 | access_count=0 未消费；回炉时置 1 并写 last_accessed |
| 微粒 id | `mz-<original_id>`，类型 meta_knowledge |
| 原文保全 | mustard_seeds.compressed_content 永久保留全文，可随时解压找回 |

### 生命周期总图

```
实体 → 剪断(compress) → 芥子 → 回炉(recycle) → 微粒
       → 再发芽/建链(sprout) → 新实体
       → 残壳归档(prune) → pruned/（落叶还田）
```

## 双脑数据契约

秩序脑（文件层）与生长脑（DB 层）必须单向为源，禁止双向写：

| 规则 | 内容 |
|------|------|
| 源方向 | wiki 文件是实体内容的唯一源，DB 是索引与派生 |
| 修复动作 | fix 类工具一律改 wiki 文件后重跑编译，禁止只写 DB |
| 剪枝动作 | 必须文件归档 + DB 清引用同时完成，缺一即双脑分歧 |
| 残壳判定 | compressed=1 且其 seed 已消费 = 残壳，进入归档队列 |

## 学习梯度（Reflect 接口）

自我提升回路拿什么当梯度？答案是矛盾与裁决，而非成败：

| 梯度源 | 内容 |
|--------|------|
| 矛盾体仲裁 | kespi-enhance 检出的矛盾对，是最合法的学习信号 |
| 三路裁决 | explore/verify/optimize 逐路指标（多样性/置信度/重排分） |
| KESPI 软门禁 | 0.65 过线 / 0.80 绿灯作为外层 Gate，不判死只调向 |

与外部训练循环（SkillOpt 式六阶段）的对接采用影子模式：
副本目录内训练，候选策略过 Gate 且分数高于基线才由 Leader 应用。

## 红灯语义修正

KESPI 红灯不等于失败，重新定义为"待回炉"：

| 信号灯 | 旧语义 | 新语义 |
|--------|--------|--------|
| 🟢 绿灯 | 人工干预 | 自主运行 |
| 🟡 黄灯 | AI 自动修复 | AI 自动修复 |
| 🔴 红灯 | 人工干预 | 待回炉：优先走压缩→回炉，仅回炉无效时升级人工 |

## 验收标准

- 芥子库不出现永久积压（未消费数不随代谢轮次单调增长）
- 残壳不残留（compressed=1 且已回炉的实体在下一轮归档清零）
- 红灯数经两轮代谢内收敛到 0
- 每个回炉微粒可沿血统链溯源到原实体
