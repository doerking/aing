# KESPI 八维质量评估体系

## 八大维度

| 维度 | 权重 | 说明 | 计算依据 |
|------|------|------|----------|
| KQ | 0.15 | 质量门禁 | confidence × 0.6 + consistency × 0.4 |
| KG | 0.12 | 生长速率 | 基于更新时间的时效性评分 |
| KA | 0.13 | 资产化就绪 | 标签、来源、元数据完整度 |
| KM | 0.12 | 代谢健康 | 近7天代谢记录数（每条+0.1，上限0.3）+ 未压缩加0.2 |
| KD | 0.13 | 密度分布 | 链接完整度（非孤儿率） |
| KC | 0.10 | 检索命中率 | 向量索引存在性 |
| KR | 0.15 | 回答准确率 | 内容完整度 |
| KB | 0.10 | 阻断事件 | 安全事件数（无事件=高） |

## 信号灯机制

- 🟢 绿灯 (≥0.80)：系统自主运行
- 🟡 黄灯 (≥0.65)：AI 自动修复
- 🔴 红灯 (<0.65)：人工干预

## 综合评分

```
overall = Σ(dimension_score × weight)
```

权重总和 = 1.00

## 维度方向

所有维度统一为 **越高越好** (1.0 = 完美, 0.0 = 最差)

## 阈值配置

```javascript
// 绿灯阈值
greenLight: 0.80

// 黄灯阈值
yellowLight: 0.65

// 红灯阈值 (低于黄灯即红灯)
redLight: 0.50
```

## 应用场景

KESPI 体系用于持续监控知识库健康度，确保知识资产的质量和可用性。每个维度可独立诊断根因并触发精准干预。

## 红灯语义

红灯不等于失败。按进化回路蓝图（evolution-loop.md），红灯实体优先进入
压缩→回炉通道转化为元知识微粒，仅回炉无效时才升级人工干预。
