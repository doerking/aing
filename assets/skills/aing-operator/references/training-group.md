# 训练组：SkillOpt 式训练闭环

## 核心观念（先想清楚再动手）

aing 体系里，**agent 是宿主（生命体），技能文档才是被训练的参数**。模型权重不动，成长靠反复编辑技能文档并用验证分数证明提升。这意味着：训练 = 改文档 + 跑验证 + 留优汰劣，任何 agent 都能执行这个循环——这正是"客户 agent 装上本技能组就多了个训练组"的原理。

## 训练现场分工

| 角色 | 位置 | 说明 |
|---|---|---|
| 宿主/生命体 | aing（<repo-root> 或部署机） | 行为的载体，只吸收不直接编辑 |
| 被训练参数 | 技能文档（skill doc） | 唯一入口，自我编译 |
| 训练现场 | `<opt-copy>`（训练副本） | 训练/推演/实验一律在此，源包严禁 |
| 训练器 | `SkillOpt-full` | 完整训练器；**不在 aing 部署包内**，第三方部署机默认没有 |

## 标准训练循环（有训练器时）

1. 定训练目标（一个可度量的行为差异，如"检索命中率"或"修复债务率"）。
2. 编辑技能文档的对应段落 → 在 OPT 跑冒烟/评测任务包。
3. 用 KESPI 软指标打 Gate（新候选分必须高于当前基线，否则淘汰）。
4. 保留 best_skill，记录三代以内分数轨迹；分数不涨的训练叫空转，停下来找原因。

## 降级循环（第三方部署机无训练器时）

没有训练器也能跑文档级训练，最小闭环：改 skill doc → 用该文档执行 2-3 个真实任务 → 对照任务结果评分 → 保留更优版本并版本化记录。纪律不变：评分必须来自真实任务结果，禁止自造指标。

## 红线

- 训练现场产物（ckpt、runs、__pycache__）留在 OPT，永不进源包。
- 训练结论入账走双证据：文档改动 + 验证分数，缺一不算"已训练"。
- aing 知识库（knowledge-base）的一问一答归档是素材来源，不是训练本身。
