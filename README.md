# aing-v2 · 知识代谢引擎（DNA 双铰链版）

> 一句话：**封闭场域内，DNA 双铰链靠 meko 中间质螺旋推进，三轴夹出加载判定，时界确定性调度。**
> 改写版说明：本引擎从旧架构从零重写，保留判断纪律与知识资产，重写全部代码栈。**本文档及本仓全部产物不含任何第三方名称、不泄露真实路径。**

---

## 一、这是什么

aing-v2 是一个**知识代谢引擎**：把会话/文档摄入（入库）→ 编译成结构化知识（双铰链）→ 蒸馏 → 关联 → 检索 → 自检 → 剪枝，全程由 **meko 中间质编排**，像 DNA 双螺旋一样两条互补链交替推进。

**核心机制四件套**：
- **DNA 双铰链拓扑**：`raw 文档 ⇄ 弱键 ⇄ 结构化实体`，解旋→复制→再螺旋，互补链互校
- **meko 中间质四顶职责**：①氢键结合（弱键可逆）②组蛋白分层（9 段）③时界编排（确定性调度）④双链互校
- **三轴夹出加载判定**：边进检索入口 = `(强度≥7) AND (类型配对合法) AND (未失效)`
- **时界确定性调度**：SLB/SLE 双模分流 + G 节点中心 + 每轮时延有界

## 二、哲学：封闭场域增强

**正因封闭，场域先增加得起来。** 开放系统能量向外耗散，场域建立不起来；封闭系统边界兜住，场域累积、稳定、增强。aing-v2 不追求开放兼容，而靠封闭场域内做到极致确定。

- 库封闭：不开放外部直改（门禁守）
- 双链封闭：raw↔wiki 互为模板，不外泄
- guard 封闭：默认断，噪声进不来

## 四、数据模型

三张表（建表即含三轴列，不走加列历史包袱）：
- **entities**：实体（含强度 tolaria_strength / 时效 last_access · invalid_at）
- **links**：边（含强度 strength / 时效 invalid_at）
- **meko_cycles**：编排日志（解旋/复制/再螺旋/互校 + 时界调度 + 通感快照）

## 五、双层蜂群（自维护 + 对外派工，不桥接）

- **内蜂群**（守内面）：只管 aing-v2 自维护，5 固定角色，**随包自洽部署**（不依赖任何外部运行时），触发源=新架构读数面（KESPI/verify/meko_cycles）。详见 [SPEC-0.5](./spec/SPEC-0.5-内外蜂群接线与部署重设.md)。
- **外蜂群**（对外面）：对外派工，载体在宿主运行时面。aing-v2 只做链路保障（弹道落盘/心跳/归因考核），不做编组指挥。
- **铁律**：两套不桥接，互不知晓对方存在。

## 六、快速开始

> 改写版：以下命令的执行位置为本仓根（`<repo-root>`）。冷启动、建库、代谢、检索、验收各命令在实现落地后由各 spec 的 acceptance criteria 钉死。

```bash
# 冷启动建库（按 SPEC-0.1 三表 schema）
node src/init-knowledge-base.js

# 一轮代谢（meko 编排双铰链螺旋推进，非直线硬串）
node src/meko-orchestrator.js

# 检索（三轴判定入口 + 命中写回 last_access）
node src/query.js "<问题>"

# 意识层仪表台（读端纯读，不扰表）
node src/memo.js --summary

# 验收门禁（无 ALL GREEN 不宣布完成）
node tools/verify-deploy.js
```

## 七、工程纪律（宪法）

4. **test count guard**：test 只加不减
