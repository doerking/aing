# 知识库怎么自己收拾烂摊子

> 写给不想看架构的人。读完你就知道：为什么你不用天天盯着它。

## 一句话

你把资料丢进去，它自己整理；放久了没人看，它自己清理；清理掉又后悔了，它还能找回来。

你什么都不用管。

## 三个画面

### 画面一：你丢进一堆乱七八糟

你今天剪了个网页、抄了段笔记、存了张截图文字。往 `raw/` 一扔就走。

秩序脑（compile.js）会自动：
- 把内容读一遍
- 归到合适的分类（Type）
- 跟已有的知识连上线（双向链接）
- 记进图谱（entities / links）
- 提交一次 Git（带编号，能追溯）

你回来时，`wiki/` 里已经多出几篇整理好的页面。你只管丢，它管归类。

### 画面二：90 天后，某篇没人看

生长脑（prune.js）会扫描：

> "这篇链接，已经 90 天没人点过了……"

它不会直接删，而是走三步：
1. 先压成「芥子」——把内容截断成前 200 字符（文本截断，不是语义压缩）
2. 藏进待定区——原文件还在，只是图谱里那根"线"暂时断开
3. 等 KESPI 打分——看它还值不值得复活

这就是「代谢」：不是删除，是回收再利用。

### 画面三：三个月后你想找回它

你突然想起那个被剪掉的知识点。两种情况：

- **还活着**（芥子成熟度 ≥ 0.75）→ 它早就被重新接入图谱，直接搜到
- **真被淘汰了**（多次复活失败）→ 原 MD 文件一直没删，去 `raw/` 或 Git 历史一翻就有

所以它永远不会真正弄丢你的东西。**断的是"链接"，不是"内容"。**

## 那你要干什么？

基本不用干。但有 4 种情况需要你出手（其余全自动）：

| 情况 | 你要做的 |
|---|---|
| KESPI 连着 3 次红灯，自己恢复不了 | 来看一眼报什么错 |
| 跨领域授粉发现了根本矛盾（比如两个理论打架） | 你拍板信哪个 |
| 想调整「什么时候算过期」这个阈值 | 改一个配置数字 |
| 想改再生冷却规则 | 改一个配置数字 |

除了这 4 种，99% 的时间你不用理它。

## 体检分是怎么管的？

手动运行 KESPI（8 项体检），出来一个 0~1 的分数：

- **≥ 0.80（绿灯）** → 一切正常，你去喝咖啡
- **0.65 < 分数 < 0.80（黄灯）** → 有亚健康，它自己调
- **≤ 0.65（红灯）** → 出问题了，卡住相关任务等你

具体那 8 项是什么、数字怎么调，看 [./02-KESPI-Threshold-Guide.md](./02-KESPI-Threshold-Guide.md)。

## 对照一下

| 你习惯的做法 | aing |
|---|---|
| 收藏一堆，从不复看 | 自动把不看的回收成芥子 |
| 用 Obsidian，得装插件配关系 | 纯 MD + Git，类型、关系原生就有 |
| 怕删错，什么都不敢删 | 只断链接、不删原文，Git 可回滚 |
| 换台电脑就废了 | 纯 MD + Git，随便换 |

## 小结

aing 是那个"会自己收拾房间的室友"：
- 你丢东西它归位（秩序脑）
- 太久不用的它收进储物箱（生长脑 / 芥子）
- 你觉得扔错了，它从箱子里或历史里翻出来（可恢复）
- 真出大事了才来叫你（4 种人工介入）

剩下的，就是让它自己跑。
