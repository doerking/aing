# 双脑冲突仲裁规则 | Conflict Resolution Protocol

> 补现有 Wiki「Dual-Brain Workflow / 双脑协作流程」的权责留白。明确双脑冲突时的处理优先级，落实「人在循环中补足深层计算」。

## 冲突场景与仲裁规则

| 冲突场景 | 仲裁优先级 | 处理逻辑 |
|----------|-----------|---------|
| **Tolaria Schema 约束 vs LLM.wiki 生成内容** | Tolaria 胜 | 生长脑生成的内容必须符合 Order Brain 的 Schema 定义，否则被 BEFORE 触发器拦截 |
| **代谢决策 vs 人工编辑** | 人工胜 | 用户手动修改 MD 后，自动跳过生长脑的当日代谢任务，避免覆盖人工输入 |
| **KESPI 红灯 vs 生长任务** | KESPI 胜 | 红灯状态下，所有非紧急生长任务暂停，优先处理阻断事件 |
| **跨域授粉张力 vs 现有图谱** | 张力优先 | 若授粉发现跨域矛盾，优先生成 `verify_conflict` 任务，而非强行合并 |

## 人工介入边界

仅在以下场景需要人工出手，其余全部自动处理：

1. **KESPI 连续 3 次红灯** 无法自动恢复
2. **跨域授粉发现核心逻辑矛盾**（如基础理论冲突）
3. **资产化阈值调整**（如 `transplant_readiness` 阈值从 0.75 调整为 0.8）
4. **再生冷却规则变更**
