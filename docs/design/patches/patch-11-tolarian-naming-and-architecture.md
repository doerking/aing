# Tolarian：宿主系统 + 内化生长引擎

> 定位：aing 的正式命名。取代「Tolaria+LLM」双脑表述，确立「单一系统、内化代谢」的架构认知。

---

## 一、命名释义

**Tolarian** = **Tolaria**（宿主）+ **-ian**（内化/属格后缀）

- **Tolaria**：源自万智牌（Magic: The Gathering）中的 Tolaria 海岛——被非瑞克西亚摧毁后重铸的知识圣地
- **-ian**：表示「属于…的」「内生于…」，暗示 LLM 代谢引擎不是外挂插件，而是长在 Tolaria 体内的器官

**命名哲学**：
> 你不是在 Tolaria 上「装了一个 LLM 插件」，你是在 Tolaria 体内「培育了一个知识代谢器官」。
> 这个器官有自己的生命周期：出生（Ingest）、生长（Sprouting）、成熟（Assetization）、衰老（Decay）、再生（Regeneration）、死亡（Archive）。

## 三、与传统方案的本质区别

| 维度 | Tolaria+LLM Wiki（双脑） | Tolarian（单一系统） |
|------|------------------------|---------------------|
| **架构形态** | 两个独立系统通过文件监听通信 | 一个系统，LLM 内化为器官 |
| **通信延迟** | 毫秒级（文件 I/O + IPC） | 微秒级（内存直调） |
| **数据一致性** | 依赖 Git Hook 和文件锁 | 天然一致，同进程共享 |
| **升级耦合** | Tolaria 和 LLM Wiki 可独立升级 | 同步升级，但一体化更强 |
| **调试难度** | 跨进程调试，日志分散 | 单进程调试，日志集中 |
| **认知模型** | 「秩序脑 + 生长脑」 | 「宿主 + 生长器官」 |
