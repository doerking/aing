# KESPI 阈值指南：80 和 65 两个数字

> 普通用户只需记两个数。本文说清它们管什么、在哪改、调大调小会怎样。

## 先看结论

| 数字 | 含义 | 默认值 | 想怎样就往哪调 |
|---|---|---|---|
| **0.80** | 绿灯线（greenLight） | 0.80 | 想更严 → 调大（0.85）；更宽松 → 调小（0.75） |
| **0.65** | 红灯线（yellowLight） | 0.65 | 同上 |
| **0.75** | 芥子复活线（transplantThreshold） | 0.75 | 同上 |

中间地带（0.65 ~ 0.80）= 黄灯，亚健康，aing 自己调，不用你管。

## KESPI 是什么

手动运行一次的 8 项体检，输出一个 0~1 的分数：

| 缩写 | 中文 | 英文 |
|---|---|---|
| KQ | 质量 | Quality |
| KG | 生长 | Growth |
| KA | 资产化 | Assetization |
| KM | 代谢 | Metabolism |
| KD | 密度 | Density |
| KC | 检索 | Retrieval |
| KR | 回答 | Response |
| KB | 阻断 | Block |

权重：`{KQ:0.15, KG:0.12, KA:0.13, KM:0.12, KD:0.13, KC:0.10, KR:0.15, KB:0.10}`

一般不建议动权重——先跑满 3 个月看数据再说。

## 三色灯怎么判

```
分数 ≥ 0.80  ──▶  🟢 绿灯：一切正常，什么都不做
0.65 < 分数 < 0.80 ──▶  🟡 黄灯：亚健康，自动调理中
分数 ≤ 0.65  ──▶  🔴 红灯：卡住非紧急生长，等你处理
```

### 红灯时会发生什么

- 暂停非紧急的生长任务（发芽、授粉）
- 优先处理阻断项（通常是 KD 多样性或 KB 备份）
- 连续 3 次红灯仍不恢复 → 这是那 4 种需要你出手的情况之一

## 绿灯线 0.80 管什么

绿灯线决定："这次体检算不算健康"。

| 调大（更严） | 调小（更松） |
|---|---|
| 0.80 → 0.85 | 0.80 → 0.75 |
| 更容易亮黄/红灯 | 更容易亮绿灯 |
| 适合：知识库已成型、追求高质量 | 适合：刚起步、资料还少 |

普通用户别动，0.80 是经验值。除非你连续几个月发现"明明没问题却老亮红灯"，再考虑调大。

## 红灯线 0.65 管什么

红灯线决定："什么时候该暂停生长去修问题"。

| 调大 | 调小 |
|---|---|
| 0.65 → 0.70 | 0.65 → 0.60 |
| 更早亮红灯（更敏感） | 更晚亮红灯（更迟钝） |
| 适合：数据宝贵、不能乱 | 适合：随便跑跑、不怕出错 |

## 0.75 管什么（别跟前两个搞混）

0.75 不是体检分，是芥子成熟度。

流程是这样的：

```
链接 90 天没被点 → 压成「芥子」（初始成熟度 0.3，文本截断前 200 字符）
        ↓ 下次 KESPI 打分
   成熟度 ≥ 0.75  →  🟢 重新接入图谱（复活）
   成熟度 < 0.75  →  继续待定，等授粉/再生
```

所以 0.75 = "够不够资格重回常用库"的门槛。调到 0.85 就很难复活（知识库更精简），调到 0.65 就什么都放回来（更全但更杂）。

## 在哪改

打开 `src/growth.config.js`，改这三个字段：

```javascript
const config = {
  kespi: {
    greenLight: 0.80,   // ← 绿灯线
    yellowLight: 0.65,  // ← 红灯线
    weights: { /* 一般不动 */ },
  },
  jiezi: {
    transplantThreshold: 0.75,  // ← 芥子复活线
    // ...
  },
};
```

改完需要重新运行脚本（当前无配置热加载）。

## 一句话总结

- **0.80 / 0.65** → 管"体检算不算健康"（三色灯）
- **0.75** → 管"被剪掉的知识够不够格复活"（芥子）
- **调大 = 更严更精简，调小 = 更松更全**

> 想不通就别调，默认值跑满 3 个月再说。
