# 层 5：记忆路由（MemR³ 簇）

## 5.1 MemR³ — Memory Retrieval via Reflective Reasoning（机制级）

**论点**：记忆系统的"最后一公里"瓶颈不在存储在策略——现有方案是"单次盲搜"（一次检索定生死），应把检索做成可自我反思的闭环 agent。

**方法**：三组件。Router 每步看状态选动作（retrieve / reflect / answer）；Evidence-Gap Tracker 全局记账——已证证据集 ℰ 与缺口集 𝒢，三性质：单调性（ℰ 只增）、完备性（若库内确有答案则 𝒢 终空）、可解释性（ℰ,𝒢 本身就是思维链）；已搜 chunk 自动 mask 防重复；reflect 节点仅推理更新状态、不消耗新检索。

**证据**：即插即用扣在 RAG/Zep 上，QA 准确率 +5~9%，多跳与时序问题最显著。

**适用边界**：管的是单查询内的闭环检索，不是跨会话记忆组织；迭代受预算约束（缺口补完或预算耗尽即停）；反思质量强依赖底层 LLM——弱模型可能空转打转。

**aing 映射**：
- 动作词表：五路 answer/retrieve/reflect/verify/ask 挂到 guide-chain 动作集；论文三路是子集，verify（证据复核）与 ask（缺口转询用户）是 aing 扩展，ask 的出口走 sensory-ends。
- **gap-detector.js 升格为 ℰ,𝒢 记账器**——这是全表最深的同构点，缺口记账骨架已存在，缺的是"把记账结果喂回路由决策"这条边。
- tri-path-orchestrator 加已搜 mask：当前三臂各自为政可能重复召回同一实体，mask 是纯增益小改动。
- 不吸收：LangGraph 依赖（aing 有自己的 guide-chain 编排，引第二编排器就是引第二真源）。

## 5.2 FluxMem — Choosing How to Remember（摘要级）

**论点**：不存在万能记忆结构；"用哪种结构组织记忆"本身应是上下文自适应的可学习决策。

**方法**：多互补记忆结构并存；结构选择器用离线监督训练，监督信号来自下游回答质量与记忆利用率；三级记忆层级；Beta 混合概率门做分布感知的记忆融合，替代脆弱的硬相似度阈值。

**证据**：PERSONAMEM +9.18%，LoCoMo +6.14%。

**适用边界**：选择器需要离线监督数据——冷启动期弱；结构越多选择器与维护成本越高；两级基准都是英文会话场景。

**aing 映射**：
- 层5 的"何时走结构路 vs 语义路 vs 图臂"可以从静态配置升级为学习型选择器，训练数据正好是层 4 的轨迹表（两层的第一个交叉点）。
- Beta 混合门 → prune/merge 里的硬阈值替代候选；门参数按阈值唯一来源纪律进 growth.config.js（envNum）。
- 不吸收：三级记忆层级——aing 已有 章节/脚本/血统/代谢 多图体系，另起层级是重复建设。

## 5.3 FadeMem（摘要级）

**论点**：主动遗忘是记忆效率的核心；"全保留或全丢弃"的二值策略是反生物的。

**方法**：双层记忆层级上差分衰减率；保留性由自适应指数衰减函数控制，三个调制因子：语义相关性 × 访问频率 × 时间模式；LLM 引导冲突消解与智能融合。

**证据**：Multi-Session Chat / LoCoMo / LTI-Bench，多跳推理与检索提升，**存储 -45%**（这个数字对运维侧最有说服力）。

**适用边界**：衰减参数敏感，调坏会把有用记忆提前抹掉（错误是静默的，发现晚）；"语义相关性"依赖嵌入质量；LLM 融合有成本与幻觉风险。

**aing 映射**：
- vitality/attention 已有衰减雏形——FadeMem 的增量是"三因子调制"参数化模板：单因子（活跃度）换三因子（活跃度 × 检索命中率 × 时间模式）。
- 落点 prune.js / recycle-seeds.js / compress.js 的淘汰线；衰减曲线族作为候选走 growth-director 门禁，KESPI 回归不降级才晋升——这本身就是层 6 流程的第一次实弹演练。
- 不吸收：LLM 融合环节——aing 的芥子/回炉机制已覆盖"相关记忆合并"语义，再叠 LLM 融合是成本翻倍。

# 层 4：路线学习（MAGMA / Agents 2.0 簇）

## 4.1 MAGMA — Multi-Graph Agentic Memory（摘要级）

**论点**：单一记忆库 + 语义相似度把时间、因果、实体信息搅成一团，是可解释性差与精度上不去的根因；记忆表示与检索逻辑必须解耦。

**方法**：每个记忆项在语义/时间/因果/实体四张正交图上表示；检索 = 策略引导的图遍历（query-adaptive 选图选路径）；结构化上下文构造，推理路径透明。

**证据**：LoCoMo + LongMemEval 上超 SOTA agentic memory 系统。

**适用边界**：四图并行的维护成本；"策略引导"需要训练好的策略（论文没给冷启动方案）；正交性是理想化假设，语义与因果在真实数据里常耦合。

**aing 映射**：
- aing 已自发长出多图（章节图 / 脚本图 / 血统链 / 代谢图）——**MAGMA 的增量价值不在"多图"而在"查询自适应选图"**：哪类问题走哪张图命中率最高，应当从轨迹表学出来。
- 血统链 ↔ MAGMA 因果图同构：可对 MAGMA 的因果边定义做血统链边语义的对照校准。
- 落点：tri-path 三臂权重从 growth.config.js 静态值 → 层 4 轨迹统计驱动的动态量（配置只留初始值与上下限，符合 envNum 纪律）。
- 不吸收：重建四图——已有图体系不推倒，只借"选图策略"。

## 4.2 Agents 2.0（未验真为论文，按范式处理）

**论点（范式级）**：Agent 1.0 是"LLM+工具循环"浅层状态机；Agent 2.0 四支柱 = 显式规划、层级委派、持久记忆、极致上下文工程；行业焦点正从"完成任务"转向"在使用中学习完成任务的方法"。

**证据**：非论文证据——行业实践（AReaL 2.0 的轨迹采集→奖励绑定→异步训练在线闭环；Anthropic《When AI Builds Itself》RSI 工程化报告）。按仲裁纪律，这一簇的可信度按"行业共识"记，不按"论文结论"记。

**aing 映射**：
- 层 4 轨迹表的 schema 就按范式四支柱反推：任务类型、脚本/工具组合、执行顺序、成功/失败、重试次数、用户修正、耗时与 KESPI 变化。字段先于算法——没有这张表，MAGMA 的"选图策略"和层 5 的"结构选择器"都没有训练数据。
- AReaL 三段式 ↔ aing 对应：轨迹采集 ↔ metabolism-log + 轨迹表；奖励绑定 ↔ KESPI 挂钩；异步训练 ↔ growth-director 门禁晋升。

# 层 6：受控自改进（Gödel Agent 簇）

## 6.1 Gödel Agent（机制级）

**论点**：更新规则本身应成为优化对象；自指（把自身代码当环境一部分读改）可行且有效。

**方法**：四步循环 self_inspect（读自身任务逻辑与自修改算法源码）→ interact（当前策略交互拿反馈）→ self_update（LLM 生成新代码/逻辑，运行时替换）→ continue_improve（无更优则递归）；技术手段 = 运行时内存检查 + monkey patching 动态替换代码与 prompt；无预定义参数搜索空间。

**证据**：数学推理、科学问答基准上超手工设计与元学习优化的 agent（北大/UC/Arizona，2024-10）。

**适用边界（重点）**：原框架**没有安全门**——环境反馈即改，改错即自增强错误；后续研究（Polaris、Darwin Gödel Machine）都在补这个洞；2026 理论侧（集智 Entropy 论文）证明"预见不完备性"：自我修改能力 ≠ 能预见修改后果，RSI 循环普遍几轮就饱和或改坏。

**aing 映射**：
- 四步映射见映射规格；**关键差异点：aing 在 self_update 与 continue_improve 之间插入四门（测试/评估/基线比较/回滚门槛）——这是 aing 对该框架最重要的改造，不是实现细节是存在理由**。
- 明示不吸收：monkey patching 运行时热替换——原论文做法与 aing 治理（候选落影子/候选区、禁直改主包、feedback-loop 禁直写 config）直接冲突，写进文档就是为了防止后来者"照论文实现"。

## 6.2 MPR — Meta-Policy Reflexion（摘要级）

**论点**：反思产物应外部化为可复用的结构化"元策略"，而不是一次性 trace；应用时软硬双路——软引导（解码偏置）+ 硬约束（规则准入检查 HAC）。

**方法**：LLM 反思 → 谓词式 Meta-Policy Memory；推理时 memory-guided decoding 与 HAC 并用；全程不动模型权重。

**证据**：AlfWorld 环境，执行准确率与稳定性优于 Reflexion 基线，HAC 进一步提升稳定性。

**适用边界**：MPM 质量上限 = 反思质量上限；谓词化有信息损失；领域规则需半自动维护；仅单环境验证，全文待读。

**aing 映射**：
- **MPR 是 B5 红线的正面教材**：反思产物外部化 + 结构化 + 准入检查——恰好就是"裁决在环 + 审计"的论文形态。B5 重设计可以直接引用它回答"为什么反思不能写回 config"：成熟方案都把反思放外部记忆，写回的是无审计的旁路。
- HAC ≈ 四门中"测试/评估"两门的论文实现模板：规则准入检查先于行动。
- 不吸收：解码期偏置——aing 不改解码过程，改的是文档与路由（aing 的"权重"就是技能文档，对应关系是 MPM↔技能文档候选，不是 MPM↔解码器）。

## 6.3 Memento 2（摘要级）

**论点**：反思记忆可以形式化为控制对象——写 = 策略评估，读 = 策略改进；无参数更新的持续学习有 RL 收敛保证。

**方法**：Stateful Reflective Decision Process 形式模型；读写循环嵌入 soft policy iteration；记忆增长使状态覆盖变密，复合策略收敛到最优。

**证据**：理论证明为主 + 长程任务经验支撑；v3（2026-01）。纯理论框架，无系统工程细节。

**适用边界**：理论假设（状态覆盖密度、环境平稳性）在真实部署常不满足；收敛保证 ≠ 收敛速度；对工程无直接操作指导——它的价值是数学背书。

**aing 映射**：
- 给 growth-director"候选分 > 基线才晋升"的门禁提供形式化依据：经验库越厚 → 状态覆盖越密 → 门禁决策越接近最优。**"积累有价值"第一次有了数学论证**。
- 反向警告（同等重要）：覆盖稀疏期（系统早期）收敛慢，KESPI 早期波动是理论预期行为，不能拿早期波动否定管线——这条写进 growth-director 的调参心智模型。

## 6.4 Hindsight（摘要级）

**论点**：记忆应是一等推理基板，**证据与推论必须分离**；把记忆当"外挂摘录层"（向量库捞 top-k 塞 prompt）是当前系统的结构性缺陷。

**方法**：四逻辑网络（世界事实 / agent 经验 / 实体摘要 / 演化信念）+ 三操作（retain / recall / reflect）；时序+实体感知层把对话流增量转成结构化记忆库；反思层对库做可追溯更新。

**证据**：LongMemEval 39% → 83.6%（20B 开源模型，同 backbone 全上下文基线），超全上下文 GPT-4o；加大 backbone 到 91.4% / LoCoMo 89.61%（最强先前开源 75.78%）。数字是本批论文里最硬的。

**适用边界**：事实 vs 信念的边界判定靠 LLM，有误判面；英文会话语料；反思层有成本。全文待读。

**aing 映射**：
- 四网络 ↔ aing 四图对照（世界事实↔章节图、agent 经验↔脚本执行记录、实体摘要↔实体/标签、演化信念↔KESPI 状态）——这是给架构文档的外部同构印证，"想/记分离"血脉又多一个独立来源。
- **"证据/推论分离"升格为治理条目**：KESPI 分数是证据，growth-director 的晋升判断是推论，审计记录两者必须分开存、不可混写。这条适合进 module-handbook。
- 三操作名（retain/recall/reflect）与层 5 动作词表对齐，路由词表引用它保持术语一致。

# 建链底座（三层共用）

## 7.1 RAKG（摘要级，代码开源）

**论点**：文档级 KGC 的瓶颈在共指消解与跨文档整合；预实体作 RAG 查询可同时治长上下文遗忘与消解复杂度。

**方法**：chunk 抽预实体 → 预实体作查询做 RAG 辅助消解 → 文档级全局建链；把 RAG 评测框架移植到 KGC，过滤 LLM 幻觉产生的实体/关系；自建 MINE 数据集。

**证据**：MINE 95.91% vs GraphRAG 89.71%（+6.2pp）；代码开源（github.com/LMMApplication/RAKG）——**候选吸收四篇里唯一有现成实现可参照的**。

**适用边界**：依赖 chunk 质量与嵌入模型；预实体查询有 API 成本；批处理文档级，非流式。

**aing 映射**：
- auto-link.js 增强"论点↔组件↔脚本↔数据表"自动连边时，直接借"预实体→RAG 查询→全局建链"管线；论文笔记入 raw/ 后的建链是第一个应用场景（吃自己的狗粮）。
- 幻觉过滤评测框架移植为建链质量门——verify-deploy C7 consistency-check 候选的论文支撑。
- 不吸收：MINE 数据集（领域不符）。

## 7.2 KG²RAG（摘要级）

**论点**：语义检索只捞孤立 chunk，忽略块间内在关系；KG 应提供块级事实关系做检索扩展与组织。

**方法**：语义检索出种子 chunk → KG 引导 chunk 扩展 → KG 引导 chunk 组织成连贯段落；HotpotQA 及变体验证。

**证据**：响应质量与检索质量双优于现有 RAG 方案（NAACL 2025）。

**适用边界**：依赖既有 KG 质量（垃圾链进垃圾出）；扩展过程有噪声传播风险；问答场景验证，全文待读。

**aing 映射**：
- "种子→扩展→组织"三段式对照 tri-path 图臂：当前图臂是并行臂，可加"图臂扩展段"（命中实体后沿边扩一跳再重排）——这是图臂从"另一路检索"升级为"检索增强"的具体形态。
- 不吸收：KG 构建（RAKG 管，各司其职）。

# 八、交叉发现（深拆的横结论）

三组论文从不同入口收敛到同三条原则，这是 aing 架构"合道"的最强外部印证：

1. **证据/推论分离**（Hindsight 四网络、MAGMA 可解释遍历、MemR³ 的 ℰ,𝒢 记账）——aing 的双证据制与审计要求站在同一边。
2. **外部化而非写回**（MPR 外部元策略、Memento 2 记忆即控制对象、Gödel Agent 的教训）——B5 红线（禁写回 config）有整条学术脉络背书。
3. **结构选择可学习**（FluxMem 选结构、MAGMA 选图、AReaL 选路线）——层 4 轨迹表是这一切的数据前提，**表设计是 M4 的真正第一优先级，先于一切算法**。

M4 落地优先级（据深拆修订）：① 层 4 轨迹表 schema（数据前提）；② 层 5 gap-detector 升格 + tri-path mask（同构最深、改动最小）；③ RAKG 管线借入 auto-link（有开源参照）；④ FadeMem 三因子衰减（走层 6 门禁练手）；⑤ 层 6 四门重设计（捆绑 B5，最后）。
