# L1/L2 映射：段位谱系与节律 → 现有读数

> **这一步做什么**：把旧包的「段位谱系 / 四通道 / 孔径 / 节律」四样东西，逐条对到 aing-v2 **已经存在**的读数与模块上，作为读表时的统一口径。
> **不做什么**：不新增 `src/` 模块、不改表结构、不加断言、不改任何判定逻辑。这是换词，不是换骨。
> **术语处置**：下文一律用工程词。旧包原词只作追溯用，落在不随包发布的对账件里，本目录不复写。

## 一、九段 → v2 落点

| 段位（工程词） | 语义 | v2 现有落点 | 形态 |
|---|---|---|---|
| 拍板 | 方向定下来、担结果 | `memo.swarm`（外派派单卡）＋ `dispatch-card.js` 七段卡 | 卡，不是动作 |
| 调度 | 拆分任务、排批次 | `dispatch-swarm.js`（批次/单元/收口）＋ `meko-field.js`（同轮派生） | 记账 |
| 情报 | 缺口、蒸馏点、趋势 | `gap-scan.js` / `distill-points.js` / `maintenance-report.js` | 读数 |
| 回单 | 结果落盘、带事实与指针 | `opt_tickets.evidence_json.result` ＋ `field_actions` | 落库 |
| 介质面 | 跨面互读（同库不同面） | `meko-field.js`（同轮派生镜像）＋ `entity_vectors` | 只读面 |
| 心跳 | 跟单保活 | `ticket-followup.js` → `evidence_json.followup.{beatAt,beats}`（SPEC-6.15） | 计数 |
| 残渣 | 归档、不占通道 | `invalid_at`（时效轴）＋ `prune.js` / `recycle.js` | 退场 |

映射口径：**九段不是九个模块，是九个读数位**。v2 里每一段都能在已有的表、字段或纯函数上指认出来，所以不需要为它建层。

## 二、四通道 → 派单/回单语义

| 通道（工程词） | 方向 | v2 对应 |
|---|---|---|
| 派单 | 拍板 → 执行点 | `dispatch-card.js` 出卡，`opt_tickets.status='dispatched'` |
| 回单 | 执行点 → 拍板 | `evidence_json.result` ＋ `verifyTickets` 收单 |
| 同层互读 | 执行点 ↔ 执行点 | `meko-field.js` 镜像、`meko-helix-crosscheck.js` 复核 |
| 介质 | 跨面只读 | `entity_vectors` / 语义检索面，只读出向 |

两条路由约束原地保留：

- **段走错通道即留介质**（core 测试 3）——派单信号不能走回单通道，`verifyTickets` 只认 `evidence_json.result`，等于已落这道闸。
- **先过膜再路由**（core 测试 7）——`ticket-gate.admit`（膜 → 粒度 → 发布门）在 `verifyTickets` 里跑在读数比对之前，顺序已对。

## 三、孔径 → 三轴与阈值

| 旧口径 | v2 落点 | 现行值 |
|---|---|---|
| 孔径（准入强度） | `tri-axis-gate.shouldEnterRetrieval` 强度轴 | `STRENGTH_THRESHOLD = 7` |
| 未达孔径衰减 | 不进检索入口，不删不罚 | 强度轴不过即不加载 |
| 类型准入 | 类型专一轴（`PAIRING_LEGAL`，未列即拒） | fail-closed |
| 有效期内才通 | 时效轴（`invalid_at IS NULL`） | 退场即失效 |
| 心跳无孔径必过 | `awaiting-return` 追单路径不受孔径约束 | SPEC-6.15 律一 |

结论：**孔径 = 三轴交集的别名**，不是新旋钮。旧包「段位越高孔径越宽」的直觉，在 v2 里换成「强度 ≥ 7 且类型配对合法且在效期内」，判定点只有一处，不重算第二套。

## 四、节律 → memo 一行读数

`memo.systemLine` 已经是节律表，七项各有出处：

| 读数项 | 出处 | 管什么 |
|---|---|---|
| 健康（ok / 非 ok） | `conservation.measureConservation` | 整体是否守恒 |
| 向量 后端口 覆盖% | `memo._vectorDiagnostics` | 语义面可用性 |
| 守恒 增长:修剪 待退N | 同上 | 边层进出 |
| 蒸馏债 N | `entities.status='pending-distillation'` | 待代谢存量 |
| 缺口 N ↑↓─ | `maintenance-report.js` | 内外部维护趋势 |
| 籽 N | `compressed_seeds.active` | 压缩记忆存量 |
| 场域动作 N | `field_actions` 总数 | 派生与升降面活跃度 |

周期侧：

- **轮次**：`meko_cycles.executed_at`，一轮一次，读数随轮更新（`kespi_scores.computed_at`）。
- **跟单节拍**：`followup.beatAt` / `beats`，超 `maxHours` 由 `staleTickets` 扫出（SPEC-6.15 律三）。
- **段位节律不另立表**：旧包「一段一拍」的节拍概念，读 `meko_cycles` 的行数就能算，不需要新增调度表。

## 五、KESPI 分段对应

`kespi.js` 现算五维（`kq` 质量 / `ka` 活跃 / `kd` 催化 / `kc` 时序相干 / `kr` 续航），`kg` `km` `kb` 当前写 NULL。

| 旧分段语义 | v2 维度 | 说明 |
|---|---|---|
| 内容够不够看 | `kq` | 正文长度 + 标签数 + 置信度 |
| 还活着没有 | `ka` | 最近访问（`last_access` 与 `access_hits` 取近） |
| 有没有往外推 | `kd` | 出向强边数 / 3 |
| 与母件同步不同步 | `kc` | 派生件与母件同轮在世占比 |
| 能不能续 | `kr` | 最近 N 轮在场占比 |

未用的 `kg` / `km` / `kb` 三列**保持 NULL**，不在这一步补算——补算属新逻辑，越界。
