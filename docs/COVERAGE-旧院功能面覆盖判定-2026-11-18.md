# 旧院功能面 → aing-v2 覆盖判定（2026-11-18）

> 目的：回答"现在这套 DNA 双铰链流程，有没有把原需求设计吃干净"。
> 方法：旧院 94 个 `src/*.js` 逐个对位到 v2 的 `src/` / `spec/` / `tools/` / STATUS 任务号，逐个给判定与证据；文件名改过的一律按功能对，不看名字。
> 口径：`覆盖`＝同功能实现在位；`改名/合并`＝换名或并入他件；`有意不迁`＝已有文字裁定（引 STATUS D# 或 spec 行）；`缺口`＝旧有功能、新院找不到对应物。

## 三、三项最容易被误判为缺口（按文件名搜会误杀）

1. **`db-time.js`** —— 无同名文件，但 UTC 安全解析已内联在 `access.js:15`、`retrieval.js:301`、`retention.js:43`、`kespi.js:19`、`gap-scan.js:18` 五处。
2. **`metabolism-panel.js` / `metabolism-log.js`** —— 无 `panel.json`、无 `metabolism_log` 表，但 SPEC-3.8 明写 v2 面板由 memo 现算；代谢日志由 `trajectory.js` 轨迹 + `meko_cycles` 承接（SPEC-6.4）。形态替换，不是缺口。
3. **`interchange-router.js`** —— degreeCap top-K 已并入 `tri-axis-gate.js`（SPEC-0.4），模糊路由被明确弃用。

另有两项接近误判：`hermes-aing-adapter`（会话入库已由 `auto-ingest` + `session-ingest` 承接，缺的只是宿主壳）、`link-filename`（v2 不落 `wiki/links` 文件，需求消失）。

## 五、SkillOpt 实况（2026-11-18 复核，更正此前结论）

**此前结论「从未产出证据档」是对的，但归因错了。** 不是它不行，是**从来没接上**：

| 事实 | 证据 |
|---|---|
| 旧院只留了对接口 | `verify-deploy.js` C20 把 SkillOpt 定为 opt-in 外部探针（`VD_SKILLOPT_PROBE=1` 才开），接不接都不判红；`simulation/` 下只有 `skillopt-task-package.json`，两份 evidence 档从未生成 |
| 真实检出在 `F:\sqa\SkillOpt` | 完整仓（SkillOpt/ skillopt_sleep/ ckpt/ configs/），git HEAD `52ad5a2` |
| 环境真就绪 | `PYTHONPATH=. python -c "from skillopt.envs.aing.adapter import AingEnvAdapter"` → **IMPORT_OK**（Python 3.11.9） |
| 从未真跑 | `F:\sqa\runs/` 空目录（2026-11-05 建，之后再无写入） |
| v2 的替代 | `gene-keeper` 本地六阶段（`rollout/reflect/aggregate/select/update/gate`），SPEC-6.8，不接外部 SkillOpt |

**结论**：SkillOpt 的处置**不能凭"没数据"下判断**——没数据的原因是没跑过。要先在 `F:\sqa` 真跑一次 rollout 拿到数，再谈去留。
