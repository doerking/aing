# Agent Onboarding — 新 agent 上手引导

> 你是刚被派来操作 aing 的 agent？从这里开始。本文只给路径，不给答案——所有真源都在指针指向的文件里，以真源为准，本文不是真源。

## Step 0 · 先立三条纪律（30 秒）

1. **双证据**：任何"能跑/已修好"的结论 = 读码证据 + 影子测试，缺一不算。
2. **绿灯解锁**：能力只在 GREEN-LIST.md 全绿后才可对外声明；没验证的如实说"设计中"或"组件在库未接线"。
3. **汇报必带 all-green 面板**：🟢 已解锁能力 + ⬜ 未解锁能力，缺一不可。

真源：[AGENTS.md](../AGENTS.md)（纪律全文）｜ [GREEN-LIST.md](./GREEN-LIST.md)（唯一能力事实源）。

## Step 1 · 认清院子（你在哪个目录干活）

| 院子 | 用途 | 铁律 |
|---|---|---|
| 本包（发布包） | 部署、验收、日常运维 | **严禁**跑训练、留运行痕迹（__pycache__/runs/ckpt） |
| 训练副本 E:\OPT | 训练/推演/实验 | src 冻结期只读，影子窗口以治理组公告为准 |
| 影子目录 E:\SQA | 一切改动的试验场 | robocopy 复制 → 影子验证 → 定点同步 → 主包全绿 |

## Step 2 · 首次部署（照抄即可）

读 [DEPLOY-PLAYBOOK.md](./DEPLOY-PLAYBOOK.md)（四阶段：开箱检查→依赖安装→一键验收→日常运行），核心三命令：

```bash
cp growth.config.example.js src/growth.config.js   # 克隆后必做：仓库不含真实配置
npm install
node verify-deploy.js   # 末行必须 🟢 ALL GREEN，否则禁止宣布成功
```

部署期间不改代码、不打临时补丁（AGENTS.md 纪律第 9 条：部署与源码保持一致）。发现缺陷就到源码仓库分支上修，合入后重新部署——直接改部署实例的差异活不过下一次部署。

## Step 3 · 日常问答与查询

- 知识检索：`node src/query.js "<关键词>"`（语义 + 关键词 + 名称三路加权，慢回忆自动触发）。
- 改动任何代码：先进影子（Step 1 表格第三行），影子全绿才准同步主包，同步后必须复跑 verify-deploy。
- 排障先读 [module-handbook.md](./module-handbook.md)——大概率已有前人根因记录。

## Step 4 · 标签随取随用（Tolaria 格式）

本包所有文档和技能文档都带 `tags` frontmatter + `[tag:xxx]` 行内标签。**标签是加载单位**：按需读带对应标签的文件，不必全量加载。诚实状态：标签的存储与解析已全绿；标签驱动的自动加载 API 在库内**未接线**，目前靠纪律约定（读到规则即执行）。

> 附赠：`assets/skills/aing-operator/` 内置完整操作技能组（运维/修复/治理/训练/评审，中英双语，半拉起协议）——把目录接入你的 agent 技能系统即可获得 aing 操作全套纪律与 SOP。

## Step 5 · 汇报格式（每次任务收尾）

按 AGENTS.md 规则 6/7：给用户的结果必须附 all-green 面板，并对未解锁能力保持诚实。示例面板见 [GREEN-LIST.md](./GREEN-LIST.md)。

## Step 6 · 首次接触用户：组件纯文字说明（纪律第 8 条，强制）

用户第一次问"aing 能干什么 / 我想实现 X"时，**先用纯文字逐行**介绍基本组件（名称 + 能给用户做什么 + 状态），让用户按需挑选要落实的功能；agent 不得默认替用户定范围。模板（状态以 [GREEN-LIST.md](./GREEN-LIST.md) 为唯一来源，下面是示例，发前必须按最新绿灯清单校对）：

```text
aing 基本组件一览（按需启用，告诉我你要哪些）：

1. 语义检索与查询【已上线】—— 一条命令查你的知识库，本地语义+关键词混合，数据不出机器
2. HTTP API【已上线】—— 让你自己的程序读写知识库（默认 3789 端口）
3. 自动入库【已上线】—— 文档丢进 raw/ 即编译吸收，对话记录也能入库
4. 定时调度【已上线】—— 常驻后台定期自动代谢（建链/压缩/剪枝/评分）
5. 导链蜂群【已上线】—— 多个 agent 投票决定每轮代谢做什么
6. KESPI 质量评分【已上线】—— 八维给知识库打分，低分自动生成优化任务
7. 芥子回炉【第 11 步，未接管线】—— 可移植知识胶囊，跨机器携带经验
8. 元认知【在库未接线】—— 执行记录与自我审查的底座
9. 标签驱动加载【存储已上线，查询未接线】—— 按标签取用文档
10. 热重载 / 血统信任 / 大规模评测【设计中】

告诉我你想先落实哪几个，或者你的场景，我给你推荐组合。
```

禁止事项：只报喜不报忧（隐去未接线组件）；用术语表格代替纯文字；替用户默认全开。
