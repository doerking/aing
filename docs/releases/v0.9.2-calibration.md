## aing v0.9.2 — Calibration & Operations（标定与运维版）

三个源码 review 架构级改进项落地 + 版本纪律对齐。核心主题：**把"拍脑袋"变成"有依据"，把"对齐"从记性变成系统行为。**

### 亮点

#### 1. 融合权重标定工具 `npm run calibrate:fusion`
- MRR@K / nDCG@K 网格评测查询融合（语义/关键词/名称）与精排（KESPI/新鲜度）权重
- 性能设计：候选召回与权重无关 → 每查询只检索一次，24 组合共享候选重打分
- 人工标注集 `tools/calibrate-set.json` 优先；缺省自动生成（实体名 + wiki 高频词）
- **小样本纪律内置**：实体 < 30 或查询 < 10 时结论仅作方向参考，不写回配置
- 当前实测（8 实体）：默认权重与最佳候选在噪声内，维持现状——工具价值在于今后改权重必须先过这把尺子

#### 2. `npm run all` 一键同起
- scheduler + api-server 同时拉起，日志带前缀；任一子进程意外退出整组 fail-fast
- Ctrl+C / SIGTERM 整组树杀（`taskkill /T`，不留代谢孤儿进程）

#### 3. scheduler 热配置
- 常驻模式轮询 `data/scheduler-config.json`（5 秒检测），改 `intervalMs` / `watchRaw` / `watchPollMs` **无需重启**
- intervalMs 钳最小 60 秒（防误配高频风暴）；删除文件即回退启动值；JSON 损坏自动维持现状
- `--once` 模式不启用热配置；metabolismTimeoutMs 不支持热改（单轮保护）

#### 4. 版本纪律对齐
- `package.json` version `1.0.0` → `0.9.1`：1.0 留给真正够分量的节点，0.9.x 序列与 tag 对齐

- 原则落地：**OPT 永远是 aing 的副本，对齐是系统行为不是记性**
